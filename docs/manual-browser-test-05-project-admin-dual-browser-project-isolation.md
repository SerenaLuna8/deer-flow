# AI 浏览器测试 05：同一项目管理员的双浏览器、双项目隔离

> **敏感测试资料：仅限本地测试环境使用，不得外传、不得提交公共仓库。测试结束后按团队安全规程处理。**

## 1. 文档目标

本文件供 AI 通过真实浏览器可见界面执行，不要求执行脚本、调用 API 或修改数据库。

本组测试只验证一个主线：同一个项目管理员账号同时登录两个彼此独立的浏览器，浏览器 A 始终操作“测试项目一”，浏览器 B 始终操作“测试项目二”。两边要并发、反复、交错地使用真实功能，确认账号级公共信息可以合理一致，而任何项目级数据、缓存、请求、事件、权限、用量和副作用都不会串到另一个项目。

| ---------- | -------------------------------- | ---------------------- | -------------------- |
| 测试项目一 | 浏览器 A，例如 Chrome            | `projectadmin@163.com` | active Project Admin |
| 测试项目二 | 浏览器 B，例如 Firefox 或 Safari | `projectadmin@163.com` | active Project Admin |

## 2. 前提审计与风险边界

### 2.1 已确认的产品事实

- Project Admin 拥有项目的全部 18 项 capability，包括项目更新、成员/渠道管理、资产读写执行和绑定、项目凭证审批、私有工作、Automation、审计、用量及生命周期管理。
- `system_admin` 与 Project Admin 是两套权限。这个账号即使是两个项目的 Admin，也不因此拥有 `/admin` 平台管理权限。
- 服务端项目上下文由“当前登录用户 + 当前项目中的 active membership”共同产生；项目对象必须再次受当前项目范围约束。
- 前端私有工作、Agent Builder、Skill Builder、Automation、治理和共享资产缓存以账号和项目共同分区；恢复中的 Run/SSE 元数据也应按账号和项目隔离。
- 项目请求删除后会立即停止进入和治理，并进入 30 天恢复窗口。固定的“测试项目一/二”不得直接做删除提交。

### 2.2 必须在执行前现场确认的假设

以下数据不在代码仓库中，不能仅凭账号名称推定。任一项不满足时，停止主测试并修复测试数据，不得把环境问题记成产品通过：

1. `projectadmin@163.com` 能正常登录，且未被停用或锁定。
2. 该账号在“测试项目一”和“测试项目二”中均为 active Project Admin。
3. 两个项目的 ID、slug、名称互不相同，且状态均为 active、未挂起、未进入待删除。
4. Private Work、Automation、Memory、项目资产和凭证所需的运行依赖已就绪；未就绪时记录真实的“功能不可用”提示并将对应场景标为环境阻塞，不在本文件中引入其他账号补齐依赖。
5. 测试 MCP、模型和凭证均为专用沙箱资源，不使用生产密钥或真实个人数据。
6. `trans-resource` 已在执行 MCP 的本地 Worker/运行时视角下监听 `localhost:8771`；若运行时无法访问该端点，应记为环境阻塞，不得私自改 URL 或伪造通过。
7. 执行负责人已从真实工具发现结果中选出：两个互不相同的唯一命中查询、一个真实多候选查询和一个确定无结果查询。不得凭空编造资源名或预期结果。

### 2.3 高风险操作限制

- 不删除、请求删除或不可逆修改固定的“测试项目一/二”。本账号双浏览器文档只验证删除确认框的取消路径；实际待删除、恢复、平台挂起和恢复均为 N/A。
- 不把真实凭证或访问令牌放入聊天、Memory、Agent 指令、Skill 文件、附件名或截图。
- 不在浏览器密码管理器中保存本地 MCP Header；测试后通过页面撤销或删除临时授权对象。不要为了制造错误而修改工作 Credential，应另建专用无效 Credential/MCP 版本。
- 不引入平台管理员、其他项目管理员、Editor、Runner、outsider 或任何其他账号执行前置、审批、降权、挂起、恢复和负向访问。本文件只由同一 `projectadmin@163.com` 在 A/B 执行；需要其他账号的场景统一记为“不属于本账号独立测试范围/N/A”。
- 发现 P0/P1 串扰后立即停止后续写操作，保留两个浏览器的页面、时间、项目 slug 和截图，避免继续操作覆盖证据。

## 4. 双浏览器拓扑、命名与取证

### 4.1 固定拓扑

1. 浏览器 A 清空本测试站点的旧会话后登录，进入“测试项目一”，记录项目一的名称、slug、项目 ID（若页面展示）及页面地址。
2. 浏览器 B 独立登录同一账号，进入“测试项目二”，记录同样信息。
3. 在 A 顶部、侧栏和页面标题中始终确认“测试项目一”；在 B 始终确认“测试项目二”。
4. A、B 并排显示。并发场景由 AI 在两个浏览器中连续快速执行，并分别记录先后顺序。
5. 全文只使用浏览器 A/B 和同一账号。允许 A/B 各自在固定项目中复制同项目标签页制造陈旧版本冲突。

### 4.2 标记数据

每次执行生成一个不含敏感信息的批次号，例如 `ISO05-20260816-01`。每个用例都创建同名但内容不同的数据，专门捕获按名称、slug 或旧缓存错误复用的缺陷。

- A 内容前缀：`P1-A-<批次>-<用例>-R<轮次>`
- B 内容前缀：`P2-B-<批次>-<用例>-R<轮次>`
- 同名对象显示名：`SAME-<批次>-<用例>-R<轮次>`
- 固定解析附件：`测试图片.png`、`测试文档.docx`、`测试表格.xlsx`；A/B 使用相同源文件，但分别上传、解析和取证。
- 对话提示词、Agent 指令、Skill 内容、MCP 描述、Memory 文本和 Automation 描述都必须包含各自项目的内容前缀。

禁止把 A/B 差异只放在对象名称中；列表错误可能被名称掩盖。必须进入详情并核对正文、版本、时间、状态和关联对象。

### 4.3 强制三轮规则

本文每个用例至少执行三轮，任何一轮未执行都不能标记“通过”。表格中的 R1/R2/R3 是最低要求：

- R1：A 先发起，B 随后发起；正常完成。
- R2：B 先发起，A 随后发起；其中指定的一侧在进行中刷新、前进/后退或关闭再打开页面。
- R3：A/B 使用完全相同的显示名并连续快速提交；按用例加入冲突、页面刷新、失败或长耗时，完成顺序应与发起顺序不同。

每轮结束都要在 A、B 两侧同时核对结果，不能只看操作发起侧。

### 4.4 每轮证据

每轮记录：批次号、用例 ID、轮次、浏览器及版本、开始/结束时间、A/B 项目 slug、操作对象 ID 或页面地址、A 截图、B 截图、预期、实际、结论。截图应带项目标题和对象正文，不记录密钥。异步场景还要记录“发起、首次事件、终态、刷新后终态”四个时间点。

## 5. 允许同步与禁止串扰的判定

### 5.1 同一账号下可合理一致的内容

| 内容                               | 合理表现                                                                                       |
| ---------------------------------- | ---------------------------------------------------------------------------------------------- |
| 登录身份                           | A/B 显示同一邮箱、同一系统角色                                                                 |
| 项目成员关系                       | 工作空间能看到该账号有权进入的两个项目；这不代表项目内部数据共享                               |
| 平台级 System Agent/Skill/MCP 定义 | 同一平台发布的只读定义和版本可在两项目都出现                                                   |
| 平台级模型目录或全局可用性         | 平台统一配置可以一致；每个会话的选择、运行和产出仍必须项目隔离                                 |
| 明确标注为账号级或平台级的策略值   | 仅策略值可以一致；页面必须清楚标明范围，不能把项目已用量混为一体                               |
| 相同本地 MCP 服务的工具和源数据    | 相同端点可发现相同工具；相同参数可返回同一客观事实，但 Run、项目绑定、缓存、审计和用量必须独立 |

是否全局注销、主题/语言或同一项目的置顶偏好会跨浏览器同步，取决于产品对该设置的明确契约，不以此单独判定项目串扰。但它绝不能改变另一个项目的对象或权限。

### 5.2 严禁从一个项目出现在另一个项目的内容

- 项目名称、slug、描述、图标、状态、成员、邀请、角色和 capability。
- 项目 Agent/Skill/MCP、草稿、版本、发布状态、默认项和 System 资产绑定状态。
- `trans-resource` 的项目 Credential、MCP asset/version、Credential grant、工具发现尝试、MCP-only Agent 依赖快照、调用参数、调用卡片、错误和缓存。端点与 Header 字面值相同不允许对象级复用。
- 项目凭证的名称、slot、授权、引用关系、状态和任何秘密值。
- 会话列表、消息、SSE/Run 事件、恢复游标、审批、建议、分支、附件、文件、Sidecar 和 Artifact。
- Memory 当前内容、待整理条目、Dream 状态、历史版本、diff 和恢复结果。
- Automation 定义、计划、时区、关联会话、运行历史、状态、错误和并发占用。
- 审计事件、用量、配额已用数、并发数、生命周期、挂起和待删除状态。
- 只应属于 A 的成功/失败 toast、红点、进度条和错误提示，不得在 B 出现；反之亦然。

即使串扰只闪现后迅速消失，也按失败处理。缓存短暂展示错误项目的私有内容是数据泄露，不接受“刷新后正常”。

## 9.1 真实本地 trans-resource MCP 隔离专项（Skill = 0）

本专项不能用 mock、静态回答或“界面显示已保存”代替真实调用。所有配置、发布、启用和调用都必须在浏览器 UI 完成，不执行 curl、脚本或数据库操作。A/B 使用同一个端点和同一个明文 Header，但每个项目都必须有完全独立的 Credential、MCP、MCP-only Agent、版本、绑定、会话和 Run。

本专项严禁绑定任何 Project/System Skill。发布 Agent 前必须在依赖摘要中截图证明 `Skill = 0`、`MCP = 1`；若界面按条目显示，则证明 Skill 列表为空且 MCP 仅有当前项目的 `trans-resource`。聊天中只通过自然语言触发 MCP，不使用 `/skill`。MCP 专项的通过、失败和清理均不得依赖后续 Skill 专项。

### 9.1.1 固定对象与真实结果判据

| 对象       | 浏览器 A / 测试项目一                                       | 浏览器 B / 测试项目二                                  | 隔离断言                                              |
| ---------- | ----------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------- |
| Credential | 显示名 `trans-resource-basic`，项目一独立 ID/version        | 同显示名 `trans-resource-basic`，项目二独立 ID/version | Secret 字面值可相同，但对象、版本和 grant ID 必须不同 |
| MCP        | 名称 `trans-resource`，URL 为固定本地端点                   | 同名称、同 URL                                         | asset/version、审批、工具发现尝试、状态和绑定必须不同 |
| Agent      | `trans-mcp-only-agent`，指令含 `P1-MCP-AGENT-*`，Skill 为 0 | 同名，指令含 `P2-MCP-AGENT-*`，Skill 为 0              | 仅绑定本项目 MCP 精确已发布版本，MCP 数为 1           |
| 会话       | 只选择项目一 MCP-only Agent                                 | 只选择项目二 MCP-only Agent                            | thread、Run、SSE、tool call/result、Artifact 独立     |

相同端点在相同参数下返回相同客观资源事实是合理的，不能据此声称串扰。因此三轮必须使用不同的 A/B 查询参数，并检查工具调用卡片或 Run 详情中的实际 MCP 名、工具名、参数和结果。仅看到模型最终文本中出现预期标记，不足以证明 MCP 被真实调用。

执行前在真实工具发现完成后填写下表。资源标识必须从当前环境的真实清单选择，不得照抄示例或臆造：

| 数据代号   | 现场填写 | 必须满足                                                                           |
| ---------- | -------- | ---------------------------------------------------------------------------------- |
| `U-A`      |          | 只用于 A，检索后恰好一个可继续查询的候选                                           |
| `U-B`      |          | 只用于 B，与 U-A 不同，检索后恰好一个候选                                          |

| `Z-A`      |          | A 的合法格式但确定零命中查询                                                       |
| `Z-B`      |          | B 的合法格式但确定零命中查询                                                       |

“空”要分别验证两层：没有给资源关键字时 MCP-only Agent 应先澄清且不调用 MCP；给出合法但零命中的 `Z-A/Z-B` 时应真实调用搜索工具并如实返回零结果。歧义查询必须先展示候选并等待用户选择，不能偷偷选择第一项；选择唯一候选后才可继续详情/路由调用。

### 9.1.2 两个 MCP-only Agent

A/B Agent 指令必须不同，且全部行为直接由 Agent 指令和 MCP 工具完成，不通过 Skill：

- A Agent 指令包含 `P1-MCP-AGENT-V1`：只能使用当前项目 `trans-resource`；回答首行输出 `[P1-MCP-AGENT-V1]`；缺少资源关键字时先澄清且不调用；零命中如实返回；多候选时列出“字段: 值”并等待选择，唯一后才继续详情/路由调用；不得输出 Authorization、Credential ID 或 Secret。
- B Agent 指令包含 `P2-MCP-AGENT-V1`：只能使用当前项目 `trans-resource`；回答首行输出 `[P2-MCP-AGENT-V1]`；缺少条件时先澄清；零命中如实返回；多候选时用 Markdown 表格列出并等待选择，唯一后才继续；结尾输出 `PROJECT-TWO-MCP-COMPLETE`；不得输出 Authorization、Credential ID 或 Secret。

两边 Agent 都只绑定各自 MCP 的精确已发布版本，Skill 依赖必须为 0。不得因为项目中已有其他 Skill/MCP 就保留默认依赖，也不得让模型通过 Skill 间接调用 `trans-resource`。

| R1   | A 先创建项目一 Credential/MCP 并审批发布，B 随后用同名、同端点、同 Header 创建项目二对象；分别触发真实工具发现，再创建各自 MCP-only Agent | 两边均发现真实工具；Credential、grant、asset、version、发现 attempt ID 不同；Agent 均为 Skill=0/MCP=1；详情不回显 Secret |

错误只使用专门的无效临时 Credential、错误 MCP version 和绑定它的临时 MCP-only Agent 产生；不得修改工作链路，也不得停止共享服务。

| ---- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |

## 17. 异常结果与缺陷分级

### P0：立即停止

- B 显示、下载或执行了 A 的消息、Memory、文件、Artifact、凭证或私有资产，或反之。
- 用“项目二 slug + 项目一对象 ID”能读取/修改项目一对象。
- 一个项目的写操作实际修改、删除、挂起、恢复或授权了另一个项目。
- MCP 专项因端点或 Header 相同而复用了另一项目的 Credential/MCP/MCP-only Agent version、Run、工具参数/结果、审计或额度记录。
- Skill 专项因 slash name 相同而复用了另一项目的 Skill/Skill-only Agent version、Run、正文、结果、审计或额度记录；出现任意 MCP/外部业务工具调用；或 `describe_skill`、`read_file` 等框架级加载指向本轮唯一绑定 Skill 之外的对象。
- Secret 在任何详情、错误、toast、地址、下载或另一个项目中回显。

### P1：阻断发布

- 另一项目的 SSE、恢复游标、loading、toast、审批或 Automation 状态串入当前项目，即使刷新后消失。
- 项目级角色、绑定、默认项、配额、用量、审计或生命周期状态被同账号错误共享。
- 晚到响应覆盖了另一项目缓存，或同项目冲突恢复丢失用户未保存内容。
- 挂起/待删除项目仍可从陈旧页面成功写入。

### P2/P3

- P2：无数据泄露，但项目标识、空态、计数、错误文案、分页或重试路径错误，影响判断或操作。
- P3：纯视觉/易用性问题，例如焦点顺序或提示不清，不影响权限与数据正确性。
