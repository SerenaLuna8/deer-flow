## 2. 执行前提、假设与风险控制

### 2.1 已确认的产品行为

- 工作空间是账户级入口；本文覆盖项目内的概览、对话、Automation、Agent、Skill、MCP、Memory、Credential、Audit 和设置。
- 资产版本不可原地覆盖：已有 Agent/Skill 的修订通常产生 Draft，再显式发布；但新建/导入项目 Skill 会原子地产生“published V1 + suspended 资产”，无凭据槽位的项目 MCP 会自动发布，带槽位 MCP 则进入 pending_approval。发布、资产启停、Agent 默认与依赖绑定仍是不同状态/动作。
- 页面使用版本号处理并发更新；并发冲突应提示刷新/重试，并尽可能保留本地草稿。
- Credential 密文提交后不应再次显示；聊天、Memory 和 Automation 均应受账户与项目双重隔离。
- 项目删除进入 30 天恢复窗口；它会立即阻止进入，并暂停相关 Automation。

### 2.2 执行前必须确认的环境条件

- 服务已启动，登录页和 `http://localhost:2026/workspace` 可访问。
- `测试项目一` 存在且本账号在项目中的实际角色显示为 `admin`。
- 至少有一个已发布、已启用、依赖就绪的可执行 Agent；否则把依赖该 Agent 的用例记为 `BLOCKED`，不得误记为失败或通过。
- 固定附件的上传生命周期不依赖模型解析能力；图片识别另需所选模型明确支持 Vision，DOCX/XLSX 解析另需所选 Agent 的运行环境具备相应文件处理能力。能力缺失时仍执行上传、移除、恢复、分支和引用测试，只把对应识别/解析子项记为 `BLOCKED-附件处理能力缺失`，不得根据文件名或模型猜测内容。
- 模型、MCP、附件处理和宿主机审批场景需要对应测试依赖；依赖在页面中不可用时按用例记录 `BLOCKED`，AI 不离开浏览器改造环境。

### 2.3 本文指定的真实本地 MCP 测试夹具

以下值由测试需求明确提供，只用于本机 `测试项目一` 的 AI 浏览器测试。它不是生产 Credential，不得复制到其他环境、聊天消息、截图或缺陷附件中。

| 字段                    | 必须使用的值                             |

| 身份认证                | `请求头`                                 |
| 请求头名称              | `Authorization`                          |
| 项目 Credential 类型    | `mcp_auth`                               |
| Credential 字段分组     | `headers`                                |
| Authorization header 值 | `Basic YWRtaW46RlBJM0clMVUzRXRnaEB3QQ==` |

执行顺序必须是：**项目 Credential 加密写入 → MCP 填写连接与认证要求 → 选择完全匹配的项目 Credential →“添加、绑定凭据并发布”→ MCP 详情“测试服务”→ 核对工具目录**。MCP 表单的“请求头名称”只填写 `Authorization`，绝不能把 `Basic ...` 值粘贴到 MCP 字段名称或 URL；明文值只在项目 Credential 的密码输入框出现一次。

每轮使用隔离资产标识，例如 `trans-resource-basic-mb02-r1` 和 `trans-resource-mb02-r1`。R2 先用 R1 的相同名称/slug 验证重复冲突，再用 `r2` 完成闭环；R3 硬刷新和重登后先核验 R2 的已发布状态，再用 `r3` 完成闭环。若页面显示本地 MCP 夹具不可使用或工具目录缺少闭环所需工具，记录 `BLOCKED-本地 MCP 夹具不可用`，保留页面可见提示，禁止改用虚构工具结果。

### 2.5 数据安全与回滚

- 所有新建数据都使用唯一名称：`MB02-{用例ID}-{轮次}-{日期时间}`。不要编辑或删除无法确认归属的既有资产、成员、Credential、对话或 Automation。
- 密码修改、Credential 撤销/删除和项目删除必须使用隔离测试数据，并在当前轮次结束前回滚。
- 不在 Credential、聊天、Agent、Skill、MCP 表单中录入真实生产密钥。本文给定的本地测试 Authorization 值只允许录入项目 Credential 的密码输入框；截图前检查页面没有密文。
- 项目删除用例每轮都必须立即从工作空间“恢复项目”，确认恢复成功后才能进入下一轮。密码成功修改后必须立即改回本文档密码并重新登录验证。
- 若共享测试环境中无法安全执行破坏性动作，记录为 `BLOCKED-环境保护`，附按钮状态、提示和阻塞原因，不得用“未发现问题”代替。

## 3. 每个用例强制执行的三轮协议

下表中的**每一个用例 ID**都至少执行三轮，不允许只执行表内步骤一次。证据表按 `用例ID-R1/R2/R3` 分开记录。

| 轮次        | 强制方式                                                                                     | 本轮额外观察点                                                        |
| ----------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| R1 基线     | 从干净页面按步骤完整操作一次                                                                 | 功能、文案、状态、数据落库和权限基线                                  |
| R2 立即重复 | 不登出、不刷新，立即用同一输入再做一次；创建类使用相同输入尝试一次后，再用唯一后缀完成第二次 | 防重复提交、幂等、重复名称/冲突、按钮 pending、列表计数和选择状态     |
| R3 恢复态   | 先硬刷新重做；然后退出登录、重新用本文账号登录，再核验结果并重做关键动作                     | 持久化、深链接、页面重开、草稿恢复/清理、项目作用域、登录态和缓存隔离 |

每轮至少保留：浏览器、开始结束时间、实际输入、关键步骤截图、实际结果、页面公开错误码（若有）、清理结果。预期相同的重复执行不得合并成一条记录。

## 4. 浏览器与通用判定

使用真实浏览器页面执行；并发用例只使用本账号的两个正常标签页。所有证据均来自页面可见内容和截图。

所有用例共同验收：无白屏、无限加载、不可恢复遮罩、重复 toast 风暴、未处理异常栈；键盘焦点可见；长文本不遮挡关键按钮；请求 pending 时不会重复生效；错误不会清空可恢复草稿；硬刷新后 URL、项目和已保存数据一致；任何页面均不得显示 Credential 明文或其他项目/其他账号的私有数据。

状态只允许：`PASS`、`FAIL`、`BLOCKED`、`NOT RUN`、`N/A`。`PASS` 必须三轮均通过；一轮失败即该 ID 为 `FAIL`；`N/A` 只能用于本文明确排除的跨账号或越权子场景，并必须写明原因，不能掩盖可执行功能未测。

## 18. MCP 与 Skill 两个独立端到端闭环

本节不是可选示例，但包含两个**互不依赖**的闭环。MCP 闭环只使用 `MB02-MCP-{轮次}` Agent/Thread/MCP/Credential，专用 Agent 的 Skill 依赖数必须为 `0`；Skill 闭环只使用 `MB02-SKILL-{轮次}` Agent/Thread/Skill，专用 Agent 的 MCP 依赖数必须为 `0`。两者不得共用 Agent、Thread、默认 Agent 状态、Automation、测试输入、截图、Run 证据或清理记录，也不得把一方的 PASS、FAIL、BLOCKED 当作另一方的前置条件或结论。

两个闭环都只能由 AI 使用 `projectadmin@163.com` 在 `测试项目一` 中执行。不得登录平台 admin、editor、runner、viewer 或“测试项目二”。R1/R2/R3 各自创建或复核本轮隔离资产、执行全部调用并独立清理。

### 18.1 MCP-only 闭环合同

1. 连接只使用 2.3 的真实本地夹具，按项目 Credential → MCP 配置/审批/发布 →“测试服务/重新测试”→工具发现的 UI 顺序完成；专用 Agent 只绑定 published、active 的 `trans-resource` MCP，Skill 依赖必须为 `0`。
2. OTN 固定走 `query_snc_list` → 唯一候选确认 → `get_snc_route`；SDH 固定走 `query_fdfr_list` → 唯一 FDFR 路径对象确认 → `get_fdfr_route`。FDFR 是 SDH 路径对象，不是与 OTN、SDH 并列的第三种类型；两套工具不得交叉调用。
3. 0 个候选时只报告未找到且不调用 route；2 个及以上候选时必须列出可区分的 ID/名称/A-Z 端并等待 AI 在同一会话选择，选择前不调用 route；1 个候选也要核对 A/Z 端后再取路由。
4. 空 route 表示“资源已定位，但 MCP 未返回路由”，不能写成资源不存在，也不能复用历史答案。
5. 本闭环只用普通自然语言触发，不创建、不选择、不激活任何 Skill，也不输入 `/skill`。Run 工具活动必须能证明真实 list/route 调用，页面、答案、截图和 Audit 不得出现 Authorization/Credential 明文。
