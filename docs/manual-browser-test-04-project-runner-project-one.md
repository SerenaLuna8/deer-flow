## 2. 角色事实、假设和前置确认

已确认：本环境中 RUNNER 进入项目后，项目侧栏只显示独立的“项目概览”，以及“工作”分组内的“会话”和“Automations”两个菜单；不得把“能力”或“项目管理”分组写成可见界面。RUNNER 可在“会话”中选择并运行环境预置的已授权 Agent（包括只绑定 Skill 或只绑定 MCP 的专项 Agent），并管理自己的 Automation；RUNNER 不进入 Agent、Skill、MCP、Memory、渠道连接、Credential、审计、用量、成员或项目设置页面，也不具备共享资产编辑、绑定、发布和项目治理能力。系统管理员与项目角色是独立权限。

执行前由 AI 通过浏览器可见界面确认：账号在测试项目一为有效 RUNNER，至少一个 Agent 和模型可选择，Skill/MCP/附件独立夹具、Automation 及通知状态夹具可见。模型停用、Scheduler 关闭、配额接近上限、Agent/MCP suspended/degraded/stale 等本角色无法创建的状态，只验证开始前已存在且当前账号可见的静态夹具。整个执行过程只能登录 `projectrunning@163.com`，不得切换管理员、编辑者或其他账号。夹具缺失时截图当前页面，并把对应子项标为 N/A 或 BLOCKED，不可写成通过；不得为补测而进入本角色侧栏不存在的页面。

测试数据统一使用 RUN-RUN日期-序号。禁止删除测试项目一、共享发布资产和他人私有数据；账号密码只用于登录，不安排修改密码。

### 2.1 本地真实 MCP 与独立 Skill 夹具

以下对象是执行环境在测试开始前已经存在的预置夹具。RUNNER 不负责创建、审批或发布，也不切换其他账号；页面不得出现完整 Authorization 值。

```json
{
  "name": "trans-resource",
  "url": "http://localhost:8771/api/mcp",
  "headers": {
    "Authorization": "Basic YWRtaW46RlBJM0clMVUzRXRnaEB3QQ=="
  }
}
```

MCP 静态夹具合同为：Transport=`HTTP（Streamable HTTP）`，URL=`http://localhost:8771/api/mcp`，认证=`请求头`，Header 名=`Authorization`，Credential 类型/组=`mcp_auth`/`headers`。明文值只由执行前 Credential 静态夹具持有，RUNNER 不录入、不查看、不替换；RUNNER 只从“会话”选择 MCP-only Agent 并查看本次 Run 的安全工具事件，不进入 MCP 页面。

MCP 独立夹具包括：published/active `trans-resource`、只绑定该 MCP且 Skill 依赖为 0 的 `trans-resource-only-agent-runner-valid`、`trans-resource-only-agent-runner-invalid-auth`、`trans-resource-only-agent-runner-suspended`、`trans-resource-only-agent-runner-revoked-credential`，以及 `runner-mcp-empty-catalog`、`runner-mcp-degraded`、`runner-mcp-stale` 状态夹具。所有错误对象与 valid 工作链路使用不同版本/授权；成功 Run 的工具事件应出现 `query_snc_list`、`get_snc_route`、`query_fdfr_list`、`get_fdfr_route`。资源数据会变化，执行前记录唯一、多候选和 0 命中样本；`北京东四香港柴湾OTN100G-1` 只作为真实调用入口。

Skill 独立夹具包括 `shift-handover-summary-runner-v1` + `handover-skill-only-agent-runner-v1`，以及 `shift-handover-summary-runner-v2` + `handover-skill-only-agent-runner-v2`；两个 Skill 的 `SKILL.md` 均声明 `allowed-tools: []`，两个 Agent 均为 Skill=1/MCP=0。Skill 只整理会话提供的交接文本：V1 输出“已完成、风险/阻塞、待办、下一步、负责人/截止时间”，缺失写“未提供”；V2 另加 P0～P3 风险等级和“信息缺口”清单。MCP 与 Skill 专项分别判定，任何一边不能作为另一边的通过证据。

纯 Skill 通过标准是 MCP 调用数为 0、外部/业务工具调用数为 0。若运行框架显示 `describe_skill`、`read_file` 等 Skill 发现/加载事件，只允许它们读取本轮唯一绑定的 Skill，并须单列为框架级证据，不能误记为 MCP 调用，也不能访问其他 Skill。

## 3. 深度重复协议

本文件每一个用例 ID 均须至少执行三轮：

1. R1：清晰会话下用唯一数据跑完整正常路径。
2. R2：更换数据立即重复，并快速双击/连点发送、保存、运行、停止、删除、接受等关键动作。
3. R3：在关键中间状态硬刷新，退出重登或关闭标签页后新建标签页，验证持久化和权限重新获取。

涉及并发/冲突时在同一浏览器另开标签页。三轮分别记录环境 revision、时间、前置数据、实际结果、页面截图、页面可见错误、缺陷号和清理状态。
