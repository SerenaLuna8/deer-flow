### 2.1 本地真实 MCP 与独立 Skill 夹具

以下配置由本地环境提供，可直接写入本测试文档。完整 Authorization 只由执行开始前已准备好的项目 Credential 静态夹具持有；EDITOR 本轮不创建、录入、批准、替换或迁移 Credential。查看 MCP 配置时，“请求头名称”只能是 `Authorization`，不得把完整值写入非秘密 Header、URL、说明或任何可回显字段。

```json
{
  "name": "trans-resource",
  "url": "http://localhost:8771/api/mcp",
  "headers": {
    "Authorization": "Basic YWRtaW46RlBJM0clMVUzRXRnaEB3QQ=="
  }
}
```

| 页面字段             | 固定测试值                                                               |
| -------------------- | ------------------------------------------------------------------------ |
| MCP 名称/标识        | `trans-resource`；已存在且配置正确时复用，不重复创建                     |
| 传输方式             | HTTP（Streamable HTTP）                                                  |
| MCP 服务地址         | `http://localhost:8771/api/mcp`                                          |
| 身份认证             | 请求头                                                                   |
| 槽位                 | `auth`                                                                   |
| 请求头名称           | `Authorization`                                                          |
| Credential 类型/分组 | `mcp_auth` / `headers`                                                   |
| Credential 字段值    | 静态夹具持有：`Authorization` = `Basic YWRtaW46RlBJM0clMVUzRXRnaEB3QQ==` |

真实工具合同：OTN 必须按 `query_snc_list(aliasname)` → 选择真实返回的唯一 `sncId` → `get_snc_route(sncId)` 执行；SDH 必须按 `query_fdfr_list(aliasname)` → 选择真实返回的唯一 `fdfrId` → `get_fdfr_route(fdfrId)` 执行。零命中不能继续 route，多候选必须先让用户选择，不能由 Agent 偷选第一项。

本文件从登录到清理只能使用 `projectedit@163.com`，不得中途登录平台管理员、项目管理员、运行者或邀请账号。两个专项必须独立，且测试开始前已由环境夹具提供可执行对象，执行过程中不等待其他账号审批、发布、改权限或恢复：

- MCP 专项：EDITOR 新增带认证槽位的 `trans-resource-edit-<批次>` 会自动进入待审批，因本角色不能批准 Credential 而不可执行；它与真实调用不串联。真实调用只使用开始前已存在的 active/published `trans-resource`、`trans-resource-only-agent-editor-valid` 和 `trans-resource-only-agent-editor-invalid-auth`；两个 Agent 的 Skill 依赖必须为 0，并且只绑定各自的 MCP 静态版本。
- Skill 新建权限终点：EDITOR 用 Builder 新建 `shift-handover-summary-edit-<批次>` 后，提交会直接形成“已发布版本 + suspended 资产”；本角色可以发布 Skill 版本，但不能 activate/suspend、管理 Credential 绑定或发布/启用 Agent。新建 Skill 在 suspended 状态下不能作为可运行依赖进入 slash/Run。
- Skill 独立可运行闭环：执行前已有两套纯 Skill 夹具：`shift-handover-summary-editor-exec-v1` + `handover-skill-only-agent-editor-v1`，以及 `shift-handover-summary-editor-exec-v2` + `handover-skill-only-agent-editor-v2`；两个 Skill 均声明 `allowed-tools: []`，两个 Agent 均 Skill=1/MCP=0。另有 active `shift-handover-summary-editor-authoring` 供 EDITOR 创建并发布 V2 修订。EDITOR 可以把当前 active V2 选入并保存到 MCP=0 的 Agent Draft，但无权发布/启用该 Agent 版本，所以该精确版本的 Run 子路径必须记 N/A；不能借管理员补做或谎称闭环。非 Main Agent 锁定精确 Skill 版本，canonical Main 则会动态带入项目全部 active MCP，严格纯 Skill 验证不得退回 Main。

这里必须区分“依赖写入 Draft”“版本发布”和“资产可执行”：EDITOR 有 `shared_assets.edit`，能发布 Skill 版本、保存 Agent Draft 的 Skill/MCP 依赖，也能发布无 Credential 槽位的 MCP 版本；但没有 `shared_assets.manage_bindings` 与 `mcp.credentials.approve`。因此，新建 suspended Skill 的“激活后执行”、新 V2 所在 Agent Draft 的“发布/启用后执行”和带认证 MCP 的“批准后执行”均为 N/A。严格纯 Skill 会话只使用开始前精确绑定的 V1/V2 执行夹具；当前版本可完成创建→写入 Agent Draft，但不能伪造后续发布→运行闭环。全程不借其他账号。

纯 Skill 通过标准是 MCP 调用数为 0、外部/业务工具调用数为 0。若运行框架显示 `describe_skill`、`read_file` 等 Skill 发现/加载事件，只允许它们读取本轮唯一绑定的 Skill，并须单列为框架级证据，不能误记为 MCP 调用，也不能访问其他 Skill。

资源库内容会变化，测试前须依据当次真实 `query_snc_list`/`query_fdfr_list` 结果分别选定一个唯一命中样本和一个多候选样本；0 命中使用带批次号的不存在名称。`北京东四香港柴湾OTN100G-1` 只作为首个真实查询输入，不把历史候选数量或路由内容写成固定预期。

## 3. 每个用例强制执行三轮

下表中的每一个用例 ID 都必须独立完成三轮，单次成功不能判定通过：

1. R1 基线轮：新建唯一数据，按正常速度完成完整流程。
2. R2 重复轮：换一组唯一数据立即再做一次，并对保存、发送、运行、删除等关键按钮做快速双击或重复提交，验证幂等、防重和状态刷新。
3. R3 持久化轮：在关键步骤后硬刷新；退出并重新登录或关闭标签页后新建标签页，再验证权限、草稿、数据和运行状态。

并发类用例额外开启同一浏览器的第二个标签页。每轮记录：前置数据、操作时间、实际结果、页面截图、页面可见错误、缺陷编号和清理结果。
