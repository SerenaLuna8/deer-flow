# Scheduled Tasks and Memory Workbench Redesign

## 目标

重新设计工作区中的“定时任务”和“记忆”页面，使两页形成一致的专注工作台体验：桌面端采用宽内容区和稳定的主从分栏，移动端自然退化为单列。此次改动只调整前端结构、组件组织和视觉样式，不修改任何后端接口、数据模型、权限、调度或记忆业务逻辑。

## 设计方向

采用已确认的“专注工作台”方向：

- 页面最大内容宽度约 `1440px`，在大屏充分利用主内容区。
- 低饱和中性色为主，沿用 DeerFlow 现有主题变量、shadcn 组件和 Tailwind 设计语言。
- 通过字号、间距、边框、轻背景和状态徽标建立层级，不引入装饰性渐变、玻璃拟态或无关动画。
- 桌面端主从区域约为 `36% / 64%`；移动端改为单列。
- 不新增第三方依赖。

## 定时任务页面

### 页面头部

头部左侧展示“定时任务”标题和现有说明语义，右侧放置主操作“新建任务”。线程过滤提示继续保留，并放在标题区域下方作为上下文提示。

### 新建任务抽屉

点击“新建任务”后，从右侧打开 `Sheet` 抽屉。抽屉承载现有创建表单的全部内容：

- 预设配方。
- 新建对话 / 复用对话选择。
- Thread ID、标题、Prompt。
- Cron / 单次执行、时间和时区。
- 现有必填校验、禁用态、错误提示和提交 payload。

创建成功后继续执行当前表单清理逻辑，并自动关闭抽屉。失败时抽屉保持打开并展示现有错误状态。`scheduled-task-create-form` 测试标识保留在抽屉内。

### 筛选与任务列表

筛选区位于工作台上方，状态筛选和类型筛选在视觉上分成两个紧凑组，但继续使用当前 `statusFilter` 和 `typeFilter` 状态及过滤逻辑。

左侧列表展示任务标题、调度类型、状态和下一次执行时间。选中项使用主题色边框和轻背景强调；任务状态使用语义化徽标。保留现有任务按钮、选择逻辑和所有 `data-testid`。

### 任务详情

右侧详情保持稳定，不因列表内容高度变化而改变结构：

- 顶部展示标题、状态和编辑入口。
- 关键元数据采用两列信息网格：执行上下文、调度类型、下次运行、最近运行、关联线程和运行次数。
- Prompt 使用独立内容块展示。
- 暂停/恢复、立即触发、删除保持现有 mutation 和确认流程。
- 编辑表单仍在详情区内展开，字段和更新 payload 不变。
- 运行记录改为清晰的纵向列表，继续展示触发方式、状态、run ID、计划时间和错误。

无选中任务、加载失败、无运行记录等状态继续使用现有文案和逻辑，只改善留白和边框表现。

## 记忆页面

### 页面头部与工具栏

页面头部展示“记忆”标题、现有说明和主要操作。操作层级为：

- “添加事实”为主按钮。
- 导入和导出为次按钮。
- “清空全部记忆”与普通操作分隔，保持破坏性样式和原确认弹窗。

搜索和“全部 / 事实 / 摘要”筛选位于统一工具栏中，继续使用当前 `query`、`deferredQuery`、`filter` 和过滤派生逻辑。

### 主从分栏

当筛选为“全部”时：

- 左侧约 36% 展示长期摘要。
- 右侧约 64% 展示记忆事实。

当筛选为“事实”时，仅事实面板显示并扩展到全宽；当筛选为“摘要”时，仅摘要面板显示并扩展到全宽。移动端无论筛选状态均为单列。

摘要继续使用现有 `buildMemorySectionGroups`、搜索过滤和 Markdown 渲染能力。视觉上按用户、历史等现有分组组织为清晰区块，不改变摘要内容或只读属性。

事实列表继续展示内容、类别、置信度、创建时间和来源链接。每条事实改为更清晰的列表行，编辑和删除按钮保持原行为、禁用态、可访问名称和确认流程。

空记忆、无匹配结果、加载和错误状态均保留现有判断和文案。

### 弹窗与数据管理

添加/编辑事实、删除事实、导入确认和清空确认弹窗保持现有字段、验证、payload、成功提示和错误提示。只允许调整间距和视觉层级。

## 组件边界

### 定时任务

`ScheduledTasksPage` 继续拥有全部 hooks、状态、派生数据和 mutations。为降低页面 JSX 密度，可将下列纯展示区域拆成同目录组件，但只能通过 props 接收现有数据和回调：

- 创建任务抽屉。
- 筛选工具栏。
- 任务列表。
- 任务详情和运行记录。

展示组件不得自行请求数据、复制 mutation 或改变 payload。

### 记忆

`MemorySettingsPage` 继续拥有全部 hooks、过滤状态、导入导出和 mutations。摘要面板与事实面板可以提取为文件内或同目录展示组件，但不得改变现有 API、校验函数和 mutation 流程。

`WorkspaceCapabilityPage` 增加显式的宽度变体，记忆页选择宽工作区；工具和技能页面维持当前宽度，避免无关视觉变化。

## 响应式与可访问性

- `lg` 及以上使用主从分栏，小屏使用单列。
- 定时任务小屏先显示列表，详情位于其后；抽屉宽度限制在可读范围内并在窄屏占满可用宽度。
- 所有按钮保留文字或 `aria-label`，状态不能只依赖颜色。
- 抽屉必须包含可访问的标题和说明，打开后由现有 Radix Sheet 管理焦点。
- 交互控件保留键盘操作和可见焦点状态。
- 遵循现有主题变量，兼容浅色与深色模式。

## 测试与验收

实现采用测试驱动：

- 更新定时任务 E2E，先验证创建表单默认不常驻页面，点击“新建任务”后在抽屉出现，提交成功后关闭且新任务出现在列表和详情中。
- 保留并运行暂停、触发、筛选回退和运行记录现有测试，证明核心逻辑未改变。
- 为记忆工作台补充前端测试，验证“全部 / 事实 / 摘要”三种模式对应的面板可见性，以及现有搜索和操作入口仍存在。
- 运行前端单元测试、相关 E2E、`pnpm check` 和 `pnpm format`。
- 在本地已登录工作区检查宽屏、窄屏、浅色和深色下的布局。

## 非目标

- 不修改定时任务或记忆的后端接口、schema、hooks、缓存 key 或 mutation payload。
- 不改变调度语义、状态流转、线程关联规则或运行记录数据。
- 不改变记忆生成、搜索匹配、导入格式、导出格式、事实验证和摘要只读规则。
- 不重设计工具、技能或其他工作区页面。
- 不引入新的数据统计、排序、分页或批量操作。
