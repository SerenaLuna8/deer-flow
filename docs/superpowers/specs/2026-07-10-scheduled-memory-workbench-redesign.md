# 定时任务与记忆工作台重设计

## 目标

将“定时任务”和“记忆”重构为一致、低噪音的专注工作台：桌面端充分利用主内容区宽度，通过稳定的主从分栏降低浏览和操作成本；移动端自然退化为单列。此次只调整前端信息架构、组件排版和视觉表达，不改变现有业务逻辑。

## 已确认方向

- 视觉方向：专注工作台。
- 桌面宽度：占满可用主内容区，内容最大宽度约 `1440px`。
- 桌面布局：约 35% 主列表或摘要，65% 详情或事实。
- 定时任务创建：由页面常驻表单改为右侧抽屉。
- 视觉语言：沿用 DeerFlow 现有 shadcn、Tailwind 和主题 token；使用克制的边框、圆角、层级和语义状态色，不引入新的设计系统、渐变背景或装饰性动效。

## 不变的核心逻辑

以下代码契约和行为必须保持不变：

- 定时任务查询、按 thread 查询、创建、更新、暂停、恢复、立即执行、删除和运行历史 hooks。
- 创建表单字段、配方填充、上下文模式、必填校验、schedule 结构、timezone 默认值及提交成功后的重置逻辑。
- 当前任务选择、过滤后选择回退、编辑态同步和删除确认逻辑。
- 记忆查询、搜索、`all / facts / summaries` 过滤、导入校验、导出、新增事实、编辑事实、删除事实和清空全部记忆逻辑。
- Memory 与 Scheduled Task 的 API、类型、缓存键、mutation、副作用、权限和错误语义。
- 现有对外 `data-testid`；因创建表单迁入抽屉而需要调整的测试交互除外。

## 共享页面骨架

两个页面都使用以下内容层级：

1. 工作区顶栏与 breadcrumb。
2. 内容页标题区：标题、说明、主要动作。
3. 紧凑工具栏：搜索或过滤控制。
4. 主工作区：桌面主从分栏，移动端单列。

内容容器使用 `w-full max-w-[1440px]`，常规桌面 padding 为 24–32px。主要卡片使用主题 `background/card`、`border`、`rounded-xl` 和轻量 `shadow-xs`，选中态通过 `border-primary/40`、低透明度 `primary` 背景和清晰焦点环表达。所有颜色继续支持现有浅色和深色主题。

不为两页建立过度抽象的跨域业务组件。可以新增一个小型、纯展示的页面标题组件，或给现有工作区页面容器增加可选内容宽度 class；领域表单和面板仍归各自页面所有。

## 定时任务页面

### 标题与工具栏

标题区左侧展示“定时任务”和现有页面语义说明，右侧放置主按钮“新建任务”。页面不再常驻创建表单。

标题下方保留现有状态与类型过滤能力，将八个独立按钮整理为两组紧凑分段控制：状态组和类型组。若 URL 含 `thread_id`，继续展示现有按 thread 过滤提示，并放在过滤栏附近。

查询错误继续使用现有错误文案，放在工具栏下方的醒目但克制的错误区域。

### 主从布局

桌面端使用 `minmax(300px, 0.36fr) / minmax(0, 0.64fr)` 两列：

- 左侧任务列表面板：面板标题与结果数量、任务条目。
- 右侧任务详情面板：当前选中任务的完整信息、操作和运行历史。

任务条目保持按钮语义与现有选择逻辑。每项突出任务名称，第二层展示 schedule 类型与状态 badge，第三层展示下次运行时间。选中项具有明确背景、边框和焦点状态。

详情面板顺序固定为：

1. 标题、状态与编辑按钮。
2. 关键元数据网格：上下文模式、thread、schedule、下次运行、最近运行。
3. Prompt 内容或现有内联编辑表单。
4. 暂停/恢复、立即执行、删除操作区。
5. 运行历史列表；每条保留 trigger、status、run ID、时间和错误信息。

大屏下详情面板可在内容滚动时保持靠近顶部，但不得制造嵌套滚动陷阱。

### 新建任务抽屉

“新建任务”打开右侧 `Sheet`，桌面宽度约 520–600px，移动端占满宽度。抽屉内容使用以下顺序：

1. 标题与简短说明。
2. 现有配方快捷项。
3. 新建对话/复用对话的上下文模式控制。
4. thread ID 条件字段。
5. 标题与 prompt。
6. 现有 `ScheduledTaskScheduleInput`。
7. 表单错误。
8. 固定底部取消与创建按钮。

提交调用、disabled 条件和成功后的字段重置保持原样；成功后额外关闭抽屉，这是纯 UI 状态变化。关闭未提交抽屉不主动清空用户输入，避免误操作丢失草稿。

## 记忆页面

### 标题与操作

标题区左侧使用现有记忆标题和说明，右侧依次为导入、导出和主要动作“添加事实”。“清空全部记忆”从主操作行移入“更多”菜单中的危险操作，仍打开原确认弹窗。

搜索框与 `all / facts / summaries` 过滤器位于独立工具栏。所有现有过滤计算保持不变。

### 主从布局

当过滤器为 `all` 时，桌面端使用约 35/65 两列：

- 左侧“长期摘要”面板：在标题区明确只读状态；按现有 group 和 section 结构展示摘要卡片，保留 Markdown 渲染、更新时间和空状态。
- 右侧“记忆事实”面板：标题显示当前可见数量，事实以紧凑行式卡片展示。

当过滤器为 `facts` 或 `summaries` 时，唯一可见面板扩展为全宽，不保留空列。搜索没有结果时继续使用现有无匹配文案。

事实条目层级：

1. 内容正文。
2. category、confidence、createdAt 和 source 元数据；采用 badge 与弱化文本组合。
3. 编辑和删除图标按钮；保留现有 title、aria-label、disabled 与回调。

导入、导出、事实编辑、事实删除和清空确认的 Dialog 内容及处理函数保持不变，只允许调整间距和视觉层级。

## 响应式规则

- `lg` 以下改为单列。
- 定时任务先显示任务列表，再显示选中详情；抽屉在窄屏为全宽。
- 记忆页 `all` 模式先显示摘要，再显示事实；单一过滤模式仅显示对应面板。
- 标题区在窄屏垂直排列，操作按钮允许换行但主要动作保持可见。
- 过滤器可换行，不允许水平溢出或依赖鼠标 hover 才能使用。

## 可访问性与状态

- 保留语义按钮、label、Dialog/Sheet 标题和现有 aria 属性。
- 新建任务按钮、抽屉关闭、过滤项、任务选择和事实操作均可键盘访问。
- 选中状态不仅依赖颜色，并提供边框/背景差异。
- 加载、空数据、过滤无结果、API 错误和 mutation pending 状态沿用现有文案与禁用逻辑。
- 尊重现有主题与 reduced-motion；此次不增加必要性不足的动画。

## 组件与文件边界

预计主要修改：

- `frontend/src/app/workspace/scheduled-tasks/page.tsx`
- `frontend/src/components/workspace/settings/memory-settings-page.tsx`
- `frontend/src/components/workspace/workspace-capability-page.tsx` 或记忆路由页，用于宽内容容器覆盖
- 相关中英文 i18n 文件，仅在现有文案无法准确表达新面板标题时添加最少字段
- `frontend/tests/e2e/scheduled-tasks.spec.ts`
- 新增或修改轻量布局契约测试，覆盖记忆分栏和过滤模式

若单文件排版继续膨胀，可提取纯展示组件；不得把 hooks、mutation 和业务状态拆散到新的隐式状态层。

## 测试与验收

采用测试驱动实现：

- 先修改定时任务 E2E，使创建流程从“点击新建任务 → 抽屉表单”开始，并确认旧实现下失败。
- 保留所有既有 `data-testid`，验证创建、选择、编辑、暂停/恢复、立即执行、删除和运行历史行为不变。
- 为响应过滤状态的布局选择增加纯函数或轻量组件测试：`all` 为双栏，`facts`/`summaries` 为单栏。
- 验证记忆搜索、过滤、Dialog 操作和事实按钮的原回调接线未改变。
- 运行相关单元测试、Scheduled Tasks E2E、`pnpm check` 和 `pnpm format`。
- 在可认证浏览器会话中检查桌面宽工作区、侧栏收起状态和窄屏单列；若认证会话不可用，以自动化测试和本地构建结果为交付证据，并明确说明限制。

## 非目标

- 不修改后端、数据库、scheduler、memory 文件格式或 API。
- 不增加任务搜索、排序、分页、统计卡片或新的过滤条件。
- 不改变定时任务 schedule、thread 上下文或执行语义。
- 不改变记忆摘要生成、事实置信度、导入覆盖或导出格式。
- 不引入新依赖、设计系统、主题或动画框架。
