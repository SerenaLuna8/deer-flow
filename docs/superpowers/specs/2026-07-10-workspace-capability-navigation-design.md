# Workspace Capability Navigation Design

## 目标

将“记忆”“工具”“技能”从设置弹窗迁移为工作区主导航能力：用户通过左侧菜单进入三个独立页面，在主内容区完成现有管理操作。设置弹窗不再展示这三个菜单项。

## 范围

本次改动只调整前端导航、路由和页面承载方式，不修改记忆、MCP 工具或技能的后端接口、数据模型、权限规则和业务行为。

迁移后保留以下现有能力：

- 记忆的查看、搜索、新增、编辑、删除、清空、导入和导出。
- MCP 工具的查看、配置和启用状态管理，以及非管理员提示。
- 技能的查看、搜索、创建和启停管理。

## 导航与路由

工作区左侧主导航新增三个永久入口，位于“定时任务”之后、频道和最近对话之前，顺序固定为：

1. 记忆：`/workspace/memory`
2. 工具：`/workspace/tools`
3. 技能：`/workspace/skills`

每个入口使用与现有设置菜单一致的语义图标。侧栏展开时显示图标和文字，收起时保留图标；当前路径对应的入口使用现有 `SidebarMenuButton` 激活样式。

## 页面结构

新增三个工作区页面。页面使用一致的主内容容器，并直接复用现有的 `MemorySettingsPage`、`ToolSettingsPage` 和 `SkillSettingsPage`，避免复制业务逻辑。

现有组件暂时保留在 `components/workspace/settings/` 目录中。它们虽然沿用历史文件名，但本身已经是可独立渲染的内容组件；本次不进行无关的目录重构。

技能页面以独立页面方式渲染时不传设置弹窗的关闭回调。创建和导航行为沿用组件当前的可选回调设计。

## 设置弹窗调整

从 `SettingsDialog` 中移除：

- `memory`、`tools`、`skills` 三个 section 类型。
- 三个菜单配置项及图标导入。
- 三个页面组件导入和内容渲染分支。

账号、外观、通知、频道和关于保持原有顺序与行为。其他设置入口（包括命令面板和“设置与更多”菜单）继续打开设置弹窗。

## 国际化

左侧入口复用现有 `t.settings.sections.memory`、`tools`、`skills` 文案，不新增重复翻译键。现有页面标题和描述继续使用各自设置文案。

## 权限与异常状态

左侧三个入口对已进入工作区的用户可见。具体能力仍由现有页面组件及 API 权限控制：例如工具管理对非管理员继续显示现有权限提示，不在导航层复制权限判断。

加载、空数据、接口错误和操作反馈继续由原页面组件处理。

## 测试与验收

采用测试驱动方式实现：

- 先添加失败测试，验证主导航包含三个入口、顺序正确、链接正确且可根据路径激活。
- 先添加失败测试，验证设置弹窗不再包含 `memory`、`tools`、`skills` 菜单和渲染分支。
- 验证三个新路由能渲染对应管理组件。
- 运行相关单元测试、`pnpm check`，并在本地页面检查展开和收起侧栏下的导航表现。

## 非目标

- 不重构记忆、MCP 或技能 API。
- 不修改权限模型。
- 不增加统一“能力管理”页或二级页签。
- 不删除设置弹窗本身，也不改变其余设置项目。
- 不在本次迁移中移动或重命名三个现有内容组件。
