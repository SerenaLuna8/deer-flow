# Scheduled Tasks Empty-State Optimization

## Goal

优化定时任务页面的空数据体验和筛选层级，让首次进入页面的用户理解页面用途并能直接创建第一条任务，同时保持现有调度、查询、筛选、选择和 mutation 逻辑不变。

## Chosen Direction

采用条件式统一空状态：

- 当当前查询返回的基础任务集合为空时，隐藏筛选栏和 36/64 主从空框，展示一个全宽引导空状态。
- 当基础任务集合非空、但状态或类型筛选后无可见任务时，保留筛选栏，展示“没有符合条件的任务”和“清除筛选”。
- 当存在可见任务时，继续使用现有 36/64 列表与详情工作台，并沿用自动选择第一条可见任务的行为。

不采用以下方向：

- 始终保留筛选栏：空数据时没有可筛选对象，会增加噪音。
- 新增统计卡、模板面板或复杂 onboarding：会扩大产品范围并引入新的业务概念。

## Page Hierarchy

页面标题区保持现有结构，在标题下新增一句说明：定时任务可按计划自动运行，并展示每次执行结果。右侧继续保留唯一主操作“创建定时任务”。

有任务时，筛选栏改为两个紧凑分组：

- 状态：全部、已启用、已暂停、已完成、已失败。
- 类型：全部、定时、单次。

分组标签使用“状态”和“类型”，不再与“全部”选项重复。选中项使用次级填充样式，避免与黑色主操作竞争视觉层级；现有 `aria-pressed`、分组语义和过滤状态保持不变。

## Empty States

### No Tasks

当 `data` 已加载且长度为 0：

- 展示现有 `Empty` 组件体系。
- 使用 Lucide `CalendarClock` 图标。
- 标题：“还没有定时任务”。
- 说明：“创建一个任务，让 DeerFlow 按计划自动完成工作。”
- 主按钮：“创建第一条任务”，复用同一个受控 Sheet trigger。
- 不显示筛选栏、列表空框或“未选择定时任务”详情框。

### No Filter Matches

当 `data.length > 0` 且 `filteredData.length === 0`：

- 保留筛选栏，帮助用户理解当前条件。
- 工作区显示一个跨两列的轻量空状态。
- 标题：“没有符合条件的任务”。
- 说明：“调整筛选条件，或清除筛选查看全部任务。”
- 次按钮：“清除筛选”，同时将 `statusFilter` 和 `typeFilter` 恢复为 `all`。

### Visible Tasks

当 `filteredData.length > 0`：

- 保留现有任务列表、详情、运行记录和全部操作。
- 不改变默认选中、筛选后选择回退、编辑、暂停、恢复、立即触发和删除流程。

## Component Boundaries

- `ScheduledTasksPage` 继续持有全部 hooks、状态和 mutations。
- 创建 Sheet 仍由当前页面的受控 `Sheet` 管理。
- 空状态复用 `frontend/src/components/ui/empty.tsx`，不新增第三方依赖或业务组件层。
- 只新增最少 i18n 文案，英语和中文结构保持一致。

## Accessibility And Responsive Behavior

- 空状态标题和说明具备清晰阅读顺序，主按钮可通过键盘打开现有 Sheet。
- “清除筛选”按钮明确恢复两个筛选状态，并保留可见焦点样式。
- 桌面空状态占满工作区可用宽度；移动端保持单列且不产生横向溢出。
- 筛选按钮继续提供 `aria-pressed`，选中状态同时由文字、背景和边框表达。

## Testing

先更新 Playwright E2E 并确认旧实现失败：

1. 零任务时显示统一空状态，筛选栏、列表和详情均不存在；空状态 CTA 可打开创建 Sheet。
2. 有任务但筛选无结果时显示筛选空状态；点击清除后任务列表和详情恢复。
3. 有任务时现有主从工作台、筛选语义、创建、暂停、触发和选择回退测试继续通过。
4. 390px 视口下空状态无横向溢出。

完成后运行目标 E2E、全量单元测试、`pnpm check`、`pnpm format` 和 `git diff --check`。

## Non-Goals

- 不增加任务搜索、排序、统计、分页、模板管理或批量操作。
- 不修改后端 API、scheduler、任务 schema、hooks、cache key 或 mutation payload。
- 不重设计创建 Sheet、任务详情或运行记录业务流程。
