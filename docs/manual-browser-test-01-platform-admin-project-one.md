## 1. 文档目的

本文档供 AI 在真实浏览器中使用平台管理员账号，对 ActWeave 管理后台及“测试项目一”的平台治理入口进行深度测试。

- 本文档不是自动化测试脚本，不要求也不允许执行测试脚本、接口脚本或数据库脚本。
- 所有步骤仅通过浏览器可见页面、地址栏、刷新、前进/后退、标签页、页面文件上传和截图完成。
- 不使用浏览器页面之外的能力，不要求其他人员配合；无法仅靠页面完成的场景不纳入本文档。
- 本文档覆盖当前代码中全部 `/admin/*` 页面，以及从管理后台进入“测试项目一”治理页的功能。

## 3. 已确认边界、分支与未验证前提

### 3.1 已确认的当前界面边界

- `/admin` 自动进入 `/admin/operations`；`/admin/assets` 自动进入 `/admin/assets/agents`；`/admin/settings` 自动进入 `/admin/settings/models`。
- 平台后台包含：运行概览、项目、任务、审计日志、系统资产、系统设置、模型设置。
- 系统 Agent、系统 Skill、系统 MCP 目录当前主要是查看型界面；系统 MCP 额外提供 Credential 授权配置。不得把页面没有的“新建/编辑/发布/删除系统资产”按钮写成可执行步骤。
- 项目列表当前只提供暂停/恢复，不提供创建、重命名、删除项目。
- `/admin/projects/{项目ID}/assets/agents` 当前是目录查看页，没有详情或作者操作。
- `/admin/projects/{项目ID}/assets/skills` 提供系统 Skill 绑定治理、项目 Skill 新建、版本创建和发布，但不提供项目 Skill 的启用/停用开关；项目 Skill 生命周期只能在普通项目工作区按实际 membership/capability 操作。
- `/admin/projects/{项目ID}/assets/mcp` 可查看已有项目 MCP、处理已有版本的提交/审批/发布，并对 active MCP 执行单向的归档/暂停治理；当前管理后台不提供新建 MCP、新建 MCP 配置或把 archived/suspended MCP 恢复为 active 的按钮。
- 项目 MCP 的“新增 MCP”“编辑配置”“测试服务/重新测试”和工具发现位于普通项目工作区 `/projects/{项目slug}/mcp`，并受实际 membership 的 `shared_assets.edit`、`shared_assets.execute`、`mcp.credentials.approve` 能力约束。
- MCP、Skill 与固定附件必须各自独立测试，禁止用同一个 Agent 组合验证：MCP 专用 Agent 的 Skill 依赖数必须为 0、MCP 依赖数为 1；Skill 专用 Agent 的 Skill 依赖数必须为 1、MCP 依赖数为 0；附件专用 Agent 的 Skill 和 MCP 依赖数都必须为 0。内容型 Skill 和附件测试均不得提及、发现或调用 `trans-resource`。
- 任务页面只允许对服务端标记为“可安全重排”的任务执行重排；不能在界面强行重排未知或不安全任务。
- 平台管理员身份不自动等于任何项目成员身份，也不自动获得项目工作区内的项目权限。

### 3.2 必须按实际成员关系执行的分支

在开始项目前先记录 `admin@163.com` 是否为“测试项目一”成员：

- 分支 A——是成员且具备对应 capability：只能由同一 `admin@163.com` 进入普通工作区，按该 membership 实际授予的能力执行标为“条件执行”的 MCP/Agent/会话、Skill/Agent/会话和附件上传/解析/识别三个相互独立的测试集；不能因为同时是平台管理员而期待额外项目权限。
- 分支 B——不是成员或缺少任一所需 capability：普通项目工作区的新增 MCP、工具发现、MCP/Skill 生命周期、Agent 创建/修订、聊天及附件上传/解析/识别均标记 `N/A（权限前置不满足）`，不得换其他账号补做，也不得宣称完成会话闭环。仍执行 `/admin/projects/{项目ID}/assets/*` 可见的 Credential、页面当前已有 pending MCP 审批、Skill 创建/版本/发布治理、Agent 目录和审计测试；不得把目录状态观察写成生命周期操作通过。
- 每次测试报告必须写明采用了分支 A 还是分支 B，并附页面证据。

### 3.3 尚未验证、需要现场确认的前提

- 实际测试环境 URL、浏览器支持矩阵、邮件登录策略、账号是否被锁定均未随本文档提供。
- “测试项目一”当前状态、项目 UUID、平台管理员是否为项目成员、是否已有足够的各状态资产/任务/审计记录均需现场确认。
- 若页面不存在“待删除项目、失败任务、旧版本 Credential、待审批 MCP、退休模型适配器”等所需样本，仅记录当前可见前置不满足并标记 N/A，不在浏览器之外构造数据。

## 4. 全局执行规则：每个场景至少三轮

本文档中每一条用例以及用例内列出的每个子场景、状态值和边界值，都必须完整执行至少三轮：

1. 第 1 轮：桌面宽屏、全新登录状态。
2. 第 2 轮：刷新页面或退出重登后重复；同时验证浏览器后退、前进以及数据持久化。
3. 第 3 轮：优先采用双标签页并发；不适合并发的只读场景改用另一条浏览器可见操作路径重复。

状态变更类用例每轮都要使用独立测试数据，或在本轮结束时恢复基线。禁止把“连续点击三次同一个已改变状态的对象”算成三轮。每轮至少记录：轮次、浏览器、时间、测试数据 ID、操作前状态、实际结果、截图、是否恢复、缺陷编号。

统一通过标准：

- 页面不得出现空白、无限加载、按钮无反馈、重复提交、越权数据、明文密钥、未本地化异常堆栈。
- 加载中必须有加载反馈；失败必须有可理解的错误和可用的重试/恢复路径；成功后列表、详情、统计和审计记录应一致。
- 提交进行中按钮应禁用；重复点击、回车、刷新和双标签页不应产生重复对象或覆盖较新的数据。
- 密码和 Credential 值不得出现在列表、详情、版本历史、地址栏或页面搜索结果中。

- 保持 2.2 的三个原文件不变；三轮均从绝对路径重新选择。AI 只依据浏览器可见的预览、解析结果与会话证据核对，不在浏览器之外打开文件，也不把附件内容复制进测试提示词或预期答案。
- 模型包含启用、暂停、默认、支持视觉、不支持视觉、适配器已退休样本。
