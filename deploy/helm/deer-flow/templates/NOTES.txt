Before application replicas start, the target must be an empty database
initialized by the exact checkout's only supported workflow:

  POSTGRES_ADMIN_URL=postgresql://.../postgres \
  DATABASE_URL=postgresql://.../deerflow make setup-db
  DATABASE_URL=postgresql://... make check-db

POSTGRES_ADMIN_URL is transient setup authority, may use the same PostgreSQL
role, and is never injected into runtime Pods. Runtime receives one
DATABASE_URL only.

Runtime Pods require the exact full_schema_v9 chain head. A known ancestor may
be upgraded only with `make upgrade-db` after a backup; unknown markers,
unmanaged non-empty schemas and catalog drift remain fail closed and require a
new empty target. Runtime Pods never migrate schema.

PROCESS AND SECRET BOUNDARIES

  • Gateway, Worker and Scheduler use the same config checksum and PostgreSQL
    authority, but only Worker executes graph code.
  • Application key domains are held in Secret:
      {{ include "deer-flow.appSecret" . }}
    JWT, Better Auth, audit, credential encryption, internal auth, proxy
    attestation and Provisioner control use independent values.
  • Chart-generated values are preserved across upgrades with lookup. Back up
    the Secret or supply existingAppSecret before production use.
  • Only Provisioner mounts a Kubernetes ServiceAccount token. Other workloads
    explicitly disable token automounting.
