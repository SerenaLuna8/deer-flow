# Memory

Memory stores structured context summaries and facts under an exact project, owner and namespace. Reads, writes, queue items and prompt injection all retain those authority coordinates.

After an admitted private run, the async Memory middleware filters the visible human/final-assistant exchange and enqueues a project update. Before processing, membership is revalidated. The updater loads the PostgreSQL snapshot, applies extracted changes with optimistic versioning and records source Thread/Run IDs for new facts.

Runs without a trusted project scope do not read, inject or persist Memory. Sync middleware hooks also fail closed.

Project members manage Memory from the project Memory page subject to capability. Import, clear and fact mutation use authenticated project APIs.
