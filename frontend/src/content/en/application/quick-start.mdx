# Quick Start

The local stack consists of Nginx, Frontend, Gateway, Worker, and an optional Scheduler. The unified entry point is `http://localhost:2026`; only Worker executes the Agent graph.

## Prerequisites

| Tool | Requirement |
| --- | --- |
| Python | 3.12+ |
| Node.js | 22+ |
| pnpm | 10.26.2+ |
| uv | Current stable release |
| PostgreSQL | An instance where a fresh target database can be created |
| Nginx | Required by the local full-stack entry point |

```bash
make check
```

<Steps>

### Open the private checkout and install

Obtain the source through the private project's approved internal distribution channel, enter the repository root, and run:

```bash
make install
```

### Generate configuration

```bash
make setup
```

The wizard creates the repository-root `config.yaml` for infrastructure
settings. It does not write model definitions or model API keys.

### Initialize PostgreSQL

Use `setup-db` for a fresh PostgreSQL target. Runtime startup never creates a database or repairs or upgrades its schema. The application role must already exist.

```bash
export POSTGRES_ADMIN_URL='<administrator URL for the postgres maintenance database>'
export DATABASE_URL='<fresh Fluva target database URL>'
make setup-db
make check-db
```

<Callout type="warning">
  Point <code>setup-db</code> only at a fresh target. Test gates must use a separate disposable PostgreSQL instance.
</Callout>

When a future release packages a migration from a known predecessor, stop the
services and take a backup before running `make upgrade-db` followed by
`make check-db`. The current head remains `schema_v1`, so today `upgrade-db`
only validates it and returns idempotently; unknown versions or Catalog drift
are never repaired automatically.

### Start and open the application

```bash
make dev
```

Open [http://localhost:2026](http://localhost:2026). `make dev` starts:

- Nginx on `2026`
- Frontend on `3000`
- Gateway on `8001`

After the first platform administrator signs in, manage model configurations
and their write-only API Keys under **Admin → System Settings → Models**.
- Worker with no public port
- Scheduler with no public port (polling is controlled by platform `automations.enabled`)

### Stop

```bash
make stop
```

</Steps>

## Logs and diagnostics

Local logs are written under `logs/`: `gateway.log`, `worker.log`, `scheduler.log`, `frontend.log`, and `nginx.log`. For configuration or startup failures, begin with:

```bash
make doctor
make support-bundle
```

See [Configuration](/docs/application/configuration) and the [Deployment Guide](/docs/application/deployment-guide) for the full boundaries.
