# Quick Start

The local stack consists of Nginx, Frontend, Gateway, Worker, and an optional Scheduler. The unified entry point is `http://localhost:2026`; only Worker executes the Agent graph.

## Prerequisites

| Tool | Requirement |
| --- | --- |
| Python | 3.12+ |
| Node.js | 22+ |
| pnpm | 10.26.2+ |
| uv | Current stable release |
| PostgreSQL | An instance where a fresh target database can be created |
| Nginx | Required by the local full-stack entry point |

```bash
make check
```

<Steps>

### Clone and install

```bash
git clone https://github.com/SerenaLuna8/deer-flow.git
cd deer-flow
make install
```

### Generate configuration

```bash
make setup
```

The wizard creates the repository-root `config.yaml`. Configure at least one model and provide referenced secrets through the root `.env` or process environment. Do not commit either local file.

### Initialize PostgreSQL

DeerFlow supports only a fresh PostgreSQL target. Runtime startup never creates a database, repairs its schema, or upgrades an old database in place. The application role must already exist.

```bash
export POSTGRES_ADMIN_URL='<administrator URL for the postgres maintenance database>'
export DATABASE_URL='<fresh DeerFlow target database URL>'
make setup-db
make check-db
```

<Callout type="warning">
  Point <code>setup-db</code> only at a fresh target. Test gates must use a separate disposable PostgreSQL instance.
</Callout>

### Start and open the application

```bash
make dev
```

Open [http://localhost:2026](http://localhost:2026). `make dev` starts:

- Nginx on `2026`
- Frontend on `3000`
- Gateway on `8001`
- Worker with no public port
- Scheduler with no public port only when `scheduler.enabled=true`

### Stop

```bash
make stop
```

</Steps>

## Logs and diagnostics

Local logs are written under `logs/`: `gateway.log`, `worker.log`, `scheduler.log`, `frontend.log`, and `nginx.log`. For configuration or startup failures, begin with:

```bash
make doctor
make support-bundle
```

See [Configuration](/docs/application/configuration) and the [Deployment Guide](/docs/application/deployment-guide) for the full boundaries.
