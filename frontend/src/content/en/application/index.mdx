# ActWeave App

<Callout type="info">
  ActWeave App is a multi-account, multi-project Super Agent application built on ActWeave Harness. Gateway admits work; Worker alone executes Agent graphs.
</Callout>

## Capabilities

| Capability | Description |
| --- | --- |
| Project workspace | Projects, members, invitations, roles, quotas, audit, and lifecycle |
| Private work | Persistent Thread, Run, upload, artifact, feedback, and durable SSE |
| Versioned assets | System/Project Agent, Skill, MCP, Credential, binding, and admitted snapshots |
| Agent harness | Sub-Agents, Memory, Plan Mode, summarization, Guardrails, and Sandbox |
| Automation | One-time and Cron admission through Scheduler, execution through Worker |
| IM connections | Project-bound provider connections using the same admission boundary |

## Architecture

```text
Browser / IM
     │
     ▼
Nginx :2026 ─────► Frontend :3000
     │
     └───────────► Gateway :8001 ─────► PostgreSQL
                                      ▲          ▲
                                      │          │
                                  Worker     Scheduler
```

- Nginx is the only public entry point.
- Frontend renders the UI; it is not an authorization authority.
- Gateway owns authentication, project authorization, Run admission, queries, and SSE replay. It never executes an Agent graph.
- Worker leases PostgreSQL jobs and is the only Agent graph executor.
- Scheduler optionally admits due Automation occurrences and never executes graph code.
- PostgreSQL stores application data, checkpoints, jobs, streams, quotas, audits, and versioned asset snapshots.

Private resources bind account, project, membership, and owner context. Isolation is enforced by the business layer and database model without PostgreSQL RLS.
