# Configuration

Infrastructure configuration lives in the repository-root `config.yaml` plus
process/tool environment variables. Copy `config.example.yaml`, then configure
PostgreSQL, sandbox, authentication, Worker and optional Scheduler settings.
Model definitions are not accepted from YAML: after startup, a system
administrator configures their versioned provider settings and encrypted
Credentials at `/admin/settings/models`.

```bash
make config
make doctor
make check-db
```

Agent, Skill, MCP, Credential and model definitions are versioned database
assets. System admins manage the model catalog and system assets; project
members manage project assets and bindings in authenticated settings. Secrets
use encrypted Credential envelopes and are never stored in browser query
caches.

Gateway, Worker and Scheduler validate the configured database and schema at startup. Use the explicit database setup/migration commands before starting application processes.

Memory processing options control extraction, injection budgets and staleness review. Memory persistence itself is PostgreSQL project/owner scoped and has no local-file provider option.
