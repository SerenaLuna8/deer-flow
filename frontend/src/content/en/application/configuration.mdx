# Configuration

Runtime configuration lives in the repository-root `config.yaml` plus environment variables. Copy `config.example.yaml`, then configure models, PostgreSQL, sandbox, authentication, Worker and optional Scheduler settings.

```bash
make config
make doctor
make check-db
```

Agent, Skill, MCP and Credential definitions are versioned database assets. System admins publish system assets; project members manage project assets and bindings in authenticated settings. Secrets use encrypted Credential envelopes and are never stored in browser query caches.

Gateway, Worker and Scheduler validate the configured database and schema at startup. Use the explicit database setup/migration commands before starting application processes.

Memory processing options control extraction, injection budgets and staleness review. Memory persistence itself is PostgreSQL project/owner scoped and has no local-file provider option.
