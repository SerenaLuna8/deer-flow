# 部署指南

ActWeave 的运行拓扑由 Nginx、Frontend、Gateway、Worker、可选 Scheduler 和可选 Provisioner 组成。PostgreSQL 是唯一应用持久化数据库，并且不由 ActWeave Compose stack 自动创建。

<Callout type="warning">
  仓库提供启动资源，但 Docker Compose、Kubernetes/Helm、浏览器、模型 provider 和 Sandbox 模式都需要在目标环境单独完成容量、安全和故障验收。本页不构成生产认证。
</Callout>

## 部署前准备

1. 在根目录生成并检查 `config.yaml`。
2. 通过 `.env` 或部署平台 secret 注入模型、认证和数据库密钥；不要把 secret 写入镜像或仓库。
3. 预先创建非 superuser 应用 role。
4. 使用全新 PostgreSQL 目标库完成显式初始化：

```bash
export POSTGRES_ADMIN_URL='<连接 postgres maintenance database 的管理员 URL>'
export DATABASE_URL='<全新 ActWeave 目标库 URL>'
make setup-db
make check-db
```

运行进程只验证目标数据库，不会建库、修复 schema 或原地升级旧数据库。

## 本地全栈

```bash
make dev       # 热更新
make start     # 本地优化构建
make stop
```

统一入口为 `http://localhost:2026`。本地日志位于 `logs/{gateway,worker,scheduler,frontend,nginx}.log`，运行状态默认位于 `backend/.deer-flow`。

## Docker 开发环境

```bash
make docker-init
make docker-start
make docker-logs
make docker-stop
```

`make docker-start` 会根据 `config.yaml` 的 Sandbox provider 判断是否需要 Provisioner。Compose 仍需要可访问的外部 PostgreSQL；不要把 `DATABASE_URL` 指向未初始化目标。

## Compose 构建模式

```bash
make up
make down
```

部署前至少确认：

- 只公开 Nginx `2026`，Gateway `8001`、Frontend `3000` 和 Provisioner `8002` 保持内部可达。
- 配置 TLS、网络访问控制、强认证密钥和 secret manager。
- Gateway、Worker 和 Scheduler 使用相同的 canonical `config.yaml` 与 `DATABASE_URL`。
- Worker readiness、Scheduler ownership、durable stream 重连和项目隔离均在目标环境通过。
- `backend/.deer-flow` 只承载本地运行文件/Sandbox 投影，不是项目业务数据或资产 catalog 权威。

## Kubernetes/Helm

Helm chart 位于 `deploy/helm/deer-flow/`。Provisioner 只负责特定 Sandbox provider 的 Pod 生命周期，不拥有项目认证、Run 准入或 Agent graph 执行权。

使用 Kubernetes 时需要自行配置 namespace、镜像、Service、Ingress/TLS、Secret、网络策略和 Sandbox 持久卷。不要把 Gateway 或 Provisioner 直接暴露到公网。

## Sandbox 选择

| 模式 | 边界 |
| --- | --- |
| `LocalSandboxProvider` | 命令在宿主环境执行，只适用于可信本地任务 |
| Container/AIO provider | 容器隔离；需要验证 Docker socket、网络和挂载权限 |
| Provisioner/Kubernetes | 通过独立服务创建 Sandbox Pod；需要集群级安全验收 |

Sandbox 隔离不替代项目授权、Credential 最小权限或网络出口控制。

## 验证

```bash
make check-db
curl http://localhost:2026/health
make doctor
```

登录后还应从 `/admin/operations` 检查 Worker、Scheduler、stream、quota 和 audit readiness，并执行真实 project-scoped Run 与 SSE 重连验证。

进一步排障见[运维与排障](/docs/application/operations-and-troubleshooting)。
