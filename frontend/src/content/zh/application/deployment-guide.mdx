# 部署指南

Fluva 的运行拓扑由 Nginx、Frontend、Gateway、Worker、可选 Scheduler 和可选 Sandbox Provisioner 组成。PostgreSQL 是唯一应用持久化数据库，必须显式准备。

<Callout type="warning">
  仓库只支持本机进程启动应用。浏览器、模型 provider 和 Sandbox 模式都需要在目标环境单独完成容量、安全和故障验收。本页不构成生产认证。
</Callout>

## 部署前准备

1. 在根目录生成并检查 `config.yaml`。
2. 通过 `.env` 或进程管理器的 secret store 注入模型、认证和数据库密钥；不要提交 secret。
3. 预先创建非 superuser 应用 role。
4. 使用全新 PostgreSQL 目标库完成显式初始化：

```bash
export POSTGRES_ADMIN_URL='<连接 postgres maintenance database 的管理员 URL>'
export DATABASE_URL='<全新 Fluva 目标库 URL>'
make setup-db
make check-db
```

运行进程只验证目标数据库，不会建库、修复或升级 schema。全新目标使用
`make setup-db`；未来受支持的已知前驱只在停服、备份后的维护窗口显式执行
`make upgrade-db`。

## 本地全栈

```bash
make dev       # 热更新
make start     # 本地优化构建
make stop
```

统一入口为 `http://localhost:2026`。本地日志位于 `logs/{gateway,worker,scheduler,frontend,nginx}.log`，运行状态默认位于 `backend/.fluva-flow`。

部署前至少确认：

- 只公开 Nginx `2026`，Gateway `8001`、Frontend `3000` 和 Provisioner `8002` 保持内部可达。
- 配置 TLS、网络访问控制、强认证密钥和 secret manager。
- Gateway、Worker 和 Scheduler 使用相同的 canonical `config.yaml` 与 `DATABASE_URL`。
- Worker readiness、Scheduler ownership、durable stream 重连和项目隔离均在目标环境通过。
- `backend/.fluva-flow` 只承载本地运行文件/Sandbox 投影，不是项目业务数据或资产 catalog 权威。

## Sandbox 选择

| 模式 | 边界 |
| --- | --- |
| `LocalSandboxProvider` | 命令在宿主环境执行，只适用于可信本地任务 |
| Container/AIO provider | 容器隔离；需要验证 Docker socket、网络和挂载权限 |
| Provisioner/Kubernetes | 通过独立服务创建 Sandbox Pod；需要集群级安全验收 |

Provisioner/Kubernetes 仅是 Sandbox provider；当前仓库不提供完整 Fluva 整栈的 Kubernetes/Helm 部署目标。

Docker 仅作为可选 AIO Sandbox runtime。使用 `make setup-sandbox` 准备镜像；独立 Kubernetes 控制服务位于 `sandbox/provisioner/`。

Sandbox 隔离不替代项目授权、Secret 最小权限注入或网络出口控制。

## 验证

```bash
make check-db
curl http://localhost:2026/health
make doctor
```

登录后还应从 `/admin/operations` 检查 Worker、Scheduler、stream、quota 和 audit readiness，并执行真实 project-scoped Run 与 SSE 重连验证。

进一步排障见[运维与排障](/docs/application/operations-and-troubleshooting)。
