# Agent 与线程

<Callout type="info" emoji="🤖">
  Agent
  是配置单元——它们定义了一组能力。线程是对话实例，带有持久化状态和历史记录。
</Callout>

## Agent

### Main 与项目默认 Agent

Main 是项目级编排 Agent，也是项目未指定自定义默认 Agent 时的回退项。每次 Run 都由服务端解析当前项目内所有有效的系统资产，以及当前项目自建且已启用的 Agent、Skill 和 MCP；Agent 与 Skill 使用各自的 Current Version，MCP 使用当前准入配置，随后把完整定义冻结到 Run Snapshot。Main 可以委派给本次准入的其他 Agent，但绝不会加载其他项目的资产。Main 不要求项目 Agent 绑定，浏览器也不会替它启用或调整依赖绑定。

项目管理员可以把一个已启用且已有 Current Version 的项目 Agent 设为默认 Agent。已配置的默认 Agent 如果失效会直接阻止创建，不会静默回退到 Main。

项目当前默认 Agent 可以直接删除。删除会将其软归档、自动清空默认配置，并让项目后续回退到 Main；已有对话、自动化、Channel、OAuth 和运行记录都会保留，不会级联删除。已经准入的 Run 继续使用冻结快照执行；删除后从既有对话发起新运行时，界面会提示该 Agent 已删除并要求切换 Agent。归档记录不再占用项目名称，可以用相同名称创建具有新 ID 的 Agent；旧会话仍绑定旧 ID，不会自动恢复。

### 自定义 Agent

ActWeave 允许你创建多个具有不同专业领域的自定义 Agent。每个 Agent 使用 ActWeave Harness 相同的 Lead Agent 运行时，但具有不同的：

- 模型（例如为一个 Agent 使用 GPT-4o，为另一个使用 Claude）
- 系统提示和指令
- 技能（例如专注于数据分析的 Agent 只加载数据分析技能）
- 工具访问（通过工具组）

与 Main 不同，自建 Agent 只加载该 Agent Current Version 明确引用的能力。Skill 依赖保存 `{scope, asset_id}`，每次 Run 准入时自动解析对应 Skill 的 Current Version；MCP 仍引用精确配置。没有引用的项目资产不会自动继承。

### 创建自定义 Agent

<Steps>

#### 通过界面

1. 打开 ActWeave 应用并进入一个项目。
2. 点击项目菜单中的 **Agents**（Agent 管理）。
3. 点击 **New Agent**（新建 Agent）。
4. 输入名称和用途说明，通过 AI 对话回答澄清问题。
5. 审阅 AI 生成的 Blueprint、假设和冲突。错误级冲突会阻止创建，必须继续对话让 AI 重新生成；只手工修改文档不会解除冲突。可在当前会话修改四项指令文档和 Agent 名称，重名时无需丢弃已有对话和设计稿。
6. Builder 会自动绑定项目中已启用的 System Skill/MCP；项目自建 Skill 按资产选择，MCP 按精确配置选择。
7. 确认后会得到一个停用的 Agent 和不可变的 Candidate Version v1。
8. Editor 或 Admin 可以激活候选版本。激活会原子设置 Current Version 并启用资产；顶部开关可以随后单独停用或重新启用同一个 Current Version。

#### 通过 API

`POST /api/projects/{project_id}/agents` 接受完整的 Agent 定义，而不是只有名称的空壳：`slug`、`display_name`、`description`、`agents_instructions`、`soul`、`identity`、`user_context`、`model_ref`、`model_settings`、`tool_groups`、`skill_refs` 和 `mcp_version_ids` 都必须显式提交。`skill_refs` 中每项是 `{scope, asset_id}`。响应同时返回停用的 Agent 资产和 Candidate Version v1；缺少完整定义会被拒绝。

Editor 和 Admin 都可以保存 Candidate Version、激活版本，以及启用或停用资产。激活使用 `POST /api/projects/{project_id}/agents/{agent_id}/versions/{version_id}/activate`，请求包含当前 `expected_revision`。历史版本只读，不能删除、修改、复制或再次激活。平台管理员的项目覆盖 API 采用相同契约；不存在全局 workspace Agent 客户端。

如果会话所有者后来只保留 `shared_assets.read`，仍可只读查看本人已保存的 Builder 会话，但不能继续对话、编辑、取消或提交。
每位用户在同一项目最多保留 8 个未完成的设计会话；达到上限时，请先恢复或取消已有设计。

</Steps>

### Agent 名称和 Slug

创建 Agent 时，`display_name` 对用户显示，系统内部使用自动派生的 ASCII `slug`（`name` 字段）来标识 Agent。

- `display_name`：对用户显示的任意字符串（例如 "数据分析师"）
- `name`（slug）：用于 API 和文件路径的 ASCII 标识符（例如 `data-analyst`）

如果派生的 slug 与同一资产作用域中的未删除 Agent 冲突，服务端会返回冲突并要求选择唯一名称。Agent 删除归档后，该 slug 可以复用于具有新 ID 的 Agent。
Builder 创建时，审阅页中的规范化名称同时作为新 Agent 的显示名和 slug；通用 API 仍允许显式分别提交 `display_name` 与 `slug`。

### Agent 存储

Agent 定义、不可变版本、Current Version 指针和项目绑定存储在 PostgreSQL 中，并通过项目资产页或系统资产管理页维护。保存 Candidate Version 不改变运行行为；每个新 Run 在准入时解析 Current Version。

## 线程生命周期

线程是对话及其所有相关状态的完整封装：消息历史、产出物、待办列表和检查点数据。

### 创建

线程在你发送第一条消息时创建。线程 ID 是自动生成的 UUID（由前端生成），用于标识所有后续请求中的对话。

输入框中的 Skill 提示跟随线程 Agent：Main 显示当前项目的全部有效 Skill，自建 Agent 只显示其 Current Version 引用的 Skill 资产。任何需要 Skill 的地方都会解析该资产的 Current Version。历史 `/skill` 消息仍使用项目展示目录解析，因此不会因为当前 Agent 或版本变化而失去可读性。

### 执行

每次你发送消息，Gateway 都重新查询该 Thread 所用 Agent 及 Skill 的 Current Version，准入一个新的 Run 并冻结完整 Run Snapshot。LangGraph 从最新检查点恢复线程状态，Worker 只执行本次冻结快照并更新状态；运行或重试期间不会再次查询 Current Version。流式事件在 Agent 工作时发送到浏览器。

如果项目 Agent 被停用，旧线程历史仍可读取，但不能继续发送、重新生成、编辑后重跑或提交 human-input。请先重新启用该 Agent，或选择其他 Agent 新建线程。

### 线程持久化配置

ActWeave 在每次 Agent 轮次后通过项目 scoped PostgreSQL checkpointer 保存线程状态。这允许：

- 在服务器重启后恢复线程。
- 在长时间间隔后继续对话。
- 在出现问题时重放或从特定时间点恢复。

线程状态和应用数据必须存储在 PostgreSQL 中，通过 `database.url` 配置共享连接：

```yaml
database:
  url: $DATABASE_URL
```

PostgreSQL 驱动已是默认依赖；独立的 `checkpointer` 配置不再接受。

### 线程数据目录

在已经创建的会话中选择、粘贴或拖入附件后，ActWeave 会立即在后台上传，输入文字不会
被锁定。发送消息只等待尚未完成的部分，并直接复用已就绪的上传结果，不会重复上传同一附件。

每个线程在 `.deer-flow/threads/{thread_id}/` 下有一个专用目录：

```
.deer-flow/threads/{thread_id}/
  user-data/
    uploads/     ← 用户上传的文件
    outputs/     ← Agent 生成的产出物
    workspace/   ← 会话工作文件
```

该目录只包含 Sandbox 工作文件投影。Thread metadata、消息、Run 状态和资产权限仍以 PostgreSQL 为唯一权威。

### 恢复线程

线程以其持久化状态自动恢复。从侧边栏选择任何过往线程即可从停止处继续——Agent 会记住所有消息和产出物。
