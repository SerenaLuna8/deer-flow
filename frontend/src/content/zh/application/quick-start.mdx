# 快速上手

本地全栈由 Nginx、Frontend、Gateway、Worker 和可选 Scheduler 组成。统一入口是 `http://localhost:2026`；Agent graph 只由 Worker 执行。

## 前置条件

| 工具 | 要求 |
| --- | --- |
| Python | 3.12+ |
| Node.js | 22+ |
| pnpm | 10.26.2+ |
| uv | 当前稳定版 |
| PostgreSQL | 一个可创建全新目标库的实例 |
| Nginx | 本地全栈入口需要 |

```bash
make check
```

<Steps>

### 进入私有项目并安装

通过项目批准的内部分发渠道取得源码，进入仓库根目录后执行：

```bash
make install
```

### 生成配置

```bash
make setup
```

向导会生成根目录 `config.yaml`。至少配置一个模型，并通过根目录 `.env` 或进程环境变量提供所引用的密钥；不要提交这两个本地文件。

### 初始化 PostgreSQL

全新 PostgreSQL 目标库使用 `setup-db`；运行进程不会在启动时建库、修复或升级 schema。目标应用 role 必须预先存在。

```bash
export POSTGRES_ADMIN_URL='<连接 postgres maintenance database 的管理员 URL>'
export DATABASE_URL='<全新 Fluva 目标库 URL>'
make setup-db
make check-db
```

<Callout type="warning">
  只把 <code>setup-db</code> 指向全新目标库。测试门禁必须使用独立、可丢弃的 PostgreSQL 实例。
</Callout>

未来版本若提供已知前驱的打包迁移，请先停服并备份，再执行 `make upgrade-db` 和
`make check-db`。当前 head 仍是 `schema_v1`，所以 `upgrade-db` 只校验并幂等返回；
未知版本或 Catalog 漂移不会自动修复。

### 启动并访问

```bash
make dev
```

打开 [http://localhost:2026](http://localhost:2026)。`make dev` 会启动：

- Nginx `2026`
- Frontend `3000`
- Gateway `8001`
- Worker（无公开端口）
- Scheduler（无公开端口；自动轮询由平台配置 `automations.enabled` 控制）

### 停止

```bash
make stop
```

</Steps>

## 日志与诊断

本地日志位于 `logs/`：`gateway.log`、`worker.log`、`scheduler.log`、`frontend.log` 和 `nginx.log`。配置或启动失败时先运行：

```bash
make doctor
make support-bundle
```

完整配置和部署边界见[配置](/docs/application/configuration)与[部署指南](/docs/application/deployment-guide)。
