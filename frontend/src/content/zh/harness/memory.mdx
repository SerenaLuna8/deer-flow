# 记忆系统

项目 Memory 为当前项目中的每个认证用户维护一份私有、带版本的 Markdown 长期文档。PostgreSQL 保存当前文档、待整理历史、Dream Run、不可变文档版本，以及每个已准入 Run 冻结的精确文档快照。project、owner 和固定的内部 namespace 都由服务端从认证请求生成，浏览器不能选择其他作用域。

Thread 摘要仍是独立数据。它只压缩一个 Thread 的模型上下文，重置长期 Memory 时会保留。

## SNIP 与待整理历史

Thread 压缩时，SNIP 对完整的早期轮次执行一次有界模型调用。通过标签校验的同一份输出会同时写入 Thread `summary_text` 和一条私有待整理历史。精确的 `(nothing)` 仍会更新 Thread 摘要，但不会创建长期历史。checkpoint receipt 与数据库事务使用幂等握手，重试不会重复归档同一次压缩。

使用 `/compact` 只执行这项 Thread 内压缩；完整可见聊天记录仍会保留。

## Dream

Dream 每次最多把最早的 20 条待整理历史归入当前文档。隔离的 Dream 会话只获得当前文档、有界历史批次，以及内存中的读取/整体替换工具；它不能访问共享 Agent、文件、Shell、Web、MCP、Skill 或 Subagent。

文档替换、不可变新版本、真实 unified diff、cursor 推进、历史正文擦除和 Job 成功会原子结算。模型、工具、格式、超时或数据库任一环节失败时，文档和待整理历史都保持不变，可以安全重试。

`/Dream` 会先压缩当前 Thread，再准入一批手动 Dream。Memory 页的“立即整理”会准入同一种 Job，但不会写入聊天消息。

## 召回

Run 准入事务只读取一次当前有界文档，并冻结成一行 Run 快照。Worker 的每个模型边界只复用这份快照；首次召回不会调用模型、向量检索或排序查询。Dream 在 Run 途中完成也不会改变该 Run 的 Memory。

启用时，完整冻结文档会作为隐藏、低权限的 Human message 注入，并明确标注它是私有数据而不是指令。关闭 Memory 后，下一个模型边界会跳过注入。重置会删除长期文档、历史、版本、Dream 记录和 Run Memory 快照，但保留聊天与 Thread 摘要。

## 项目 Memory 页面

项目页面只展示：

- 当前长期文档、版本、更新时间和待整理数量；
- “立即整理”和正在执行的 Dream 状态；
- 包含处理条数与真实 diff 的 Dream/恢复记录；
- 每个已保存文档版本及明确的恢复确认。

恢复会把所选历史内容写成一个新版本，不会回退历史 cursor 或删除之后的记录。`/dream-log [version]` 会打开这份历史；`/dream-restore <version>` 会先确认再调用恢复 API。这些命令都不会进入普通 Agent 聊天流。

没有可信项目私有 scope 的 Run 不能读取、注入、整理、恢复或重置 Memory。
