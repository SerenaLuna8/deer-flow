# 配置

<Callout type="info" emoji="⚙️">
  基础设施行为由 <code>config.yaml</code> 驱动。模型定义由平台管理员在
  <strong>Admin → 系统设置 → 模型</strong> 中单独管理，并存储在 PostgreSQL。
</Callout>

Fluva 将基础设施进程配置与数据库治理设置明确分开，使部署可重现、可审计，
并且易于按环境定制。

## 配置文件位置

Fluva 使用以下优先级顺序解析 `config.yaml`：

1. 显式传递给 `AppConfig.from_file(config_path)` 的路径。
2. `ACT_WEAVE_CONFIG_PATH` 环境变量。
3. 仓库根目录中的 `config.yaml`。

如果这些路径都不存在，应用程序在启动时会报错。

要使用自定义位置：

```bash
export ACT_WEAVE_CONFIG_PATH=/path/to/my-config.yaml
```

## 环境变量插值

任何字段值都可以使用 `$VAR_NAME` 语法引用环境变量：

```yaml
database:
  url: $DATABASE_URL
```

这使密钥不出现在配置文件本身中，变量在运行时从进程环境解析。

## `use` 字段

许多配置条目使用 `use:` 字段来指定要实例化的 Python 类或对象，格式为：

```
package.subpackage.module:ClassName
```

或对于模块级对象：

```
package.subpackage.module:variable_name
```

示例：

```yaml
sandbox:
  use: deerflow.sandbox.local:LocalSandboxProvider

tools:
  - use: deerflow.community.tavily.tools:web_search_tool
    api_key: $TAVILY_API_KEY
```

这是 Fluva 实现可插拔性而不硬编码类引用的方式。

## 模型 provider 设置

平台管理员在 **Admin → 系统设置 → 模型** 中配置 provider adapter、provider
模型名、能力和有界的 provider 专用 JSON。API Key 直接加密写入所属 Model
configuration，绝不存入 `config.yaml` 或由 API 返回。

每个 Run 都会固定准入时的精确模型载荷和 Secret Generation，因此之后的管理变更不会
静默改变已经排队的工作。

## 配置版本

`config.yaml` 包含追踪 schema 版本的 `config_version` 字段：

```yaml
config_version: 1
```

当 schema 更改（新字段、重命名章节）时，此数字增加。如果你本地的 `config.yaml` 落后于当前版本，运行：

```bash
make config-upgrade
```

这将 `config.example.yaml` 中的新字段合并到你现有的 `config.yaml` 中，而不覆盖你的自定义内容。

## 最小配置示例

最小有效的 `config.yaml` 需要 PostgreSQL 连接和一个沙箱。对话开始前，还必须由
system admin 在管理页面配置至少一个 active 的数据库模型：

```yaml
config_version: 1

database:
  url: $DATABASE_URL

sandbox:
  use: deerflow.sandbox.local:LocalSandboxProvider

tools:
  - use: deerflow.community.ddg_search.tools:web_search_tool
  - use: deerflow.community.jina_ai.tools:web_fetch_tool
  - use: deerflow.sandbox.tools:ls_tool
  - use: deerflow.sandbox.tools:read_file_tool
  - use: deerflow.sandbox.tools:write_file_tool
  - use: deerflow.sandbox.tools:bash_tool
```

从仓库根目录的 `config.example.yaml` 开始，取消注释你需要的章节。
