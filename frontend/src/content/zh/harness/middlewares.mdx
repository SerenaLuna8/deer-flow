# 中间件

<Callout type="info" emoji="🔌">
  中间件包裹 Lead Agent 中的每次 LLM
  调用。它们是添加跨领域行为（如记忆、摘要压缩、澄清和 token
  追踪）的主要扩展点。
</Callout>

每次 Lead Agent 调用 LLM 时，都会先后执行一条**中间件链**。中间件可以读取和修改 Agent 的状态、向系统提示注入内容、拦截工具调用，并对模型输出做出反应。

这种设计使 Agent 核心保持简单稳定，同时允许丰富的可组合行为分层叠加。

## 链的工作方式

中间件链在每次 Agent 调用时根据当前配置和请求参数构建一次。中间件按以下规范顺序注册：

1. 运行时中间件（错误处理、线程数据、上传、悬空工具调用修补）
2. `DynamicContextMiddleware` — 当前日期和 Run 固定的记忆上下文
3. `SkillActivationMiddleware` — slash skill 激活
4. `DurableContextMiddleware` — 捕获持久摘要、委托和技能引用状态
5. `SummarizationMiddleware` — 上下文压缩（如果启用）
6. `TodoMiddleware` — 任务列表管理（仅计划模式）
7. `TokenUsageMiddleware` — token 追踪（如果启用）
8. `TitleMiddleware` — 自动生成线程标题
9. `ViewImageMiddleware` — 图像细节注入（如果模型支持视觉）
10. `DeferredToolFilterMiddleware` — 隐藏延迟工具 schema（如果启用工具搜索）
11. `SystemMessageCoalescingMiddleware` — 合并面向 provider 的 system messages
12. `ToolCallControl` — 仲裁重复调用与 Run/Task 内部工具调用 hard limit
13. `HostExecutionBatchBarrierMiddleware` — 隔离 Local 主机执行审批批次（仅 Local approval profile）
14. `SubagentLimitMiddleware` — 限制并行子 Agent 调用（如果启用子 Agent）
15. `TokenBudgetMiddleware` — 每次运行的 token 预算限制（如果启用）
16. 自定义中间件（如有）
17. `SafetyFinishReasonMiddleware` — provider 安全终止后抑制工具执行（如果启用）
18. `ClarificationMiddleware` — 拦截澄清请求（始终作为注册链尾）

顺序很重要。Durable context 会在摘要压缩之前捕获已委托任务的派发状态、终态结果和已加载的技能引用，确保它们不会随原始 transcript 压缩而丢失。LangGraph 会按注册顺序的反向 dispatch `after_model` hook，因此 ToolNode 前的有效路径是 Safety → Custom → Token Budget → Subagent Limit → Host Execution Batch Barrier → ToolCallControl。自定义中间件不能切开受保护的 Subagent Limit → Host Execution Batch Barrier → ToolCallControl 仲裁序列。Clarification 保持为结构性的注册链尾。

## 中间件参考

### ClarificationMiddleware

拦截澄清工具调用，并将其转换为面向用户的信息请求。当模型决定在继续之前需要询问用户某事时，此中间件会将该请求呈现出来。

**配置**：由 `guardrails.clarification` 设置控制。

---

### ToolCallControl

在 ToolNode 执行前仲裁完整工具调用批次。它把重复调用检测与内部工具调用 hard limit 保持为两种独立语义，并只准入确定性的可执行前缀。

System Runtime Policy v6 为主 Agent 和 Sub-Agent Task 使用不同的计数绑定：主 Agent 在同一 Run 内持续累计，`task` 委托调用本身计入主 Agent；每个 Sub-Agent Task 按自己的执行标识从独立额度开始计数，多个并行 Task 互不占用额度，也没有额外的 Run 汇总上限。相同 checkpoint receipt 的重放不会在其精确绑定中重复消费额度；达到上限后，只停止该绑定后续的内部工具调用。

**配置**：平台设置 `/admin/settings/system` 中的 `internal_tool_call_limits.lead_per_run` 与 `internal_tool_call_limits.subagent_per_task`；默认分别为 `200` 和 `50`，并冻结到新准入的 Run。已准入 Run 与历史 v2–v5 策略继续使用其冻结的 Lead/Sub-Agent 全 Run 共享上限，不会被转换为 v6 计数。

---

### DynamicContextMiddleware

加入当前日期提醒；当私有 Run 启用 Memory 时，通过 Worker 签发的 authority 读取该 Run 冻结的有界 Memory 文档。每个模型边界复用同一份精确快照，并把完整文档作为隐藏、低权限 Human message 注入。这个中间件不整理或更新长期 Memory。

长期写入链路独立运行：SNIP 把通过校验的压缩输出归档为待整理历史，Scheduler 或手动请求再准入 durable `memory_dream` Job 交给 Worker。文档、Dream 和版本合同参见[记忆系统](/docs/harness/memory)。

---

### SubagentLimitMiddleware

限制 Agent 在单次轮次中可以进行的并行子 Agent 任务调用数量。这防止 Agent 生成无限数量的并发子 Agent。

**配置**：每次请求配置中的 `subagent_enabled` 和 `max_concurrent_subagents`。

---

### TitleMiddleware

在第一次交互后自动为线程生成标题。`title.model_name` 为空时使用系统默认模型；模型调用失败时回退到从用户第一条消息截取的本地标题。

**配置**：平台设置 `/admin/settings/system` 中的 `agent_runtime.title`，不是 `config.yaml`。

```yaml
title:
  enabled: true
  max_words: 6
  max_chars: 60
  model_name: null # 系统默认模型；也可指定系统模型 UUID
```

---

### TodoMiddleware

当计划模式激活时，维护一个对用户可见的结构化任务列表。Agent 使用 `write_todos` 工具，随着完成复杂目标，将任务标记为 `pending`、`in_progress` 或 `completed`。

**激活**：在请求配置中设置 `is_plan_mode: true` 时自动启用。不需要 `config.yaml` 条目。

---

### TokenUsageMiddleware

追踪每次模型调用的 LLM token 消耗，并以 `info` 级别记录。对于了解长时序任务中 token 的使用位置很有帮助。

**配置**：`config.yaml` 中的 `token_usage:` 部分。

```yaml
token_usage:
  enabled: true
```

---

### DurableContextMiddleware

在摘要压缩原始 transcript 之前，将长期运行事实捕获到明确的线程状态 channel 中。它记录压缩摘要、已委托任务的状态/结果，以及已加载的 `SKILL.md` 引用，并在后续模型调用中作为隐藏 durable context 数据投影进去。

后端会在 durable context 捕获之前写入有界的结构化 task 结果和技能读取元数据。前端 task card 读取结构化 task status/result 字段；task 结果文本只作为展示内容，不再作为 wire protocol 解析。

**配置**：内置。`summarization.skill_file_read_tool_names` 控制哪些读取工具会被视为技能引用读取；设为 `[]` 可关闭 durable 技能引用捕获。

---

### SummarizationMiddleware

当对话变长时，对旧消息进行摘要以减少上下文大小。生成的摘要存入线程状态，并在后续模型调用中作为隐藏的 durable context 数据投影进去，在不把旧消息继续留在活跃 transcript 中的情况下保留含义。

摘要压缩只处理当前 Thread Context，不会 flush、排队或更新长期 Memory。

**配置**：`config.yaml` 中的 `summarization:` 部分。详见下方详细配置。

---

### ViewImageMiddleware

当当前模型支持视觉（`supports_vision: true`）时，此中间件拦截 `view_image` 工具调用，并将图像内容直接注入到模型的上下文中以便分析。

**激活**：当解析的模型具有 `supports_vision: true` 时自动启用。

---

### DeferredToolFilterMiddleware

当工具搜索启用时，此中间件从模型上下文中隐藏延迟工具 schema。工具通过 `tool_search` 工具按需发现，而不是预先全部列出，从而减少上下文使用。

**配置**：`config.yaml` 中的 `tool_search.enabled: true`。

## 摘要压缩配置详解

`SummarizationMiddleware` 是长时序任务中影响最大的中间件之一。完整配置参考如下：

```yaml
summarization:
  enabled: true

  # 摘要使用的模型（null = 使用默认模型）
  # 推荐使用轻量级、经济的模型，如 "gpt-4o-mini"
  model_name: null

  # 触发条件——上下文估算 Token 达到该值时运行摘要（null = 不自动触发）
  trigger_tokens: 320000

  # 摘要后保留多少最近历史（仅支持按 Token 数）
  keep:
    type: tokens
    value: 64000 # 最多保留最近 64000 个 token 的历史

  # 为摘要器准备消息时要裁剪的最大 token 数
  trim_tokens_to_summarize: 15564

  # 自定义摘要提示词（null = 使用默认 LangChain 提示词）
  summary_prompt: null
```

**保留策略**：仅支持 `tokens` 一种类型。摘要后中间件最多保留最近 `value` 个 token 的历史（默认 `64000`）。按消息数、按上下文占比的保留方式已移除，不再接受。

## 编写自定义中间件

自定义中间件可以注入到链中用于专业用途。中间件必须实现 `langchain.agents.middleware` 中的 `AgentMiddleware` 接口：

```python
from langchain.agents.middleware import AgentMiddleware

class MyMiddleware(AgentMiddleware):
    async def on_start(self, state, config):
        # 在模型调用前运行
        return state, config

    async def on_end(self, state, config):
        # 在模型调用后运行
        return state, config
```

自定义中间件在注册顺序中位于 Token Budget 之后、Safety 之前，因此它的 `after_model` hook 在 Safety 之后、Token Budget 之前运行。它不能切开受保护的 Subagent Limit → Host Execution Batch Barrier → ToolCallControl 仲裁序列。
